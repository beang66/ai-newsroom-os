# Critique v0.3 — 범위와 완료 조건

주 4~5건을 송고하는 기자의 마지막 점검을 돕는다. 모든 문장에 출처를 요구하거나, 경고를 모두 없애야 송고할 수 있게 만들지 않는다. 현재는 명시적인 제한 규칙을 구현한 로컬 프로토타입이다. 일곱 영역을 넣었다는 것이 각 영역의 모든 오류를 판별한다는 뜻은 아니다.

## 구현한 검사

| 영역 | 실제 탐지 조건 | 판단하지 않는 것 |
|---|---|---|
| 사실관계 | 관련 제목·본문의 확정/계획 표현, 유사 문장의 수치 차이, 검색 후보와 날짜·부정·확정 수준 차이 | 외부 세계의 사실 여부, 최신 사실, 원자료 자체의 진위 |
| 숫자·통계 | 단순 수량·단위 정규화 비교, A→B 증감률과 방향, %와 %p, 두 항목 합계, 0 기준값 | 복합 수량식, 통계적 유의성, 표본설계 자동 검증 |
| 인용·출처 | 큰따옴표 인용의 유사 원문 차이, 같은 인용의 이름+직책 화자 차이, 선택 자료에서 원문 미검색 안내 | 녹취 진위, 익명 취재원 신뢰도, 인용 맥락 전체 |
| 논리적 연결 | 원자료가 인과 미확인을 명시했는데 인과를 단정한 경우, 일부·표본→전체 확대 후보 | 포괄적 논증 평가, 정치적 편향 점수 |
| 맞춤법·오탈자 | 아래 8개 패턴과 정확한 위치·수정 후보 | 한국어 전체 사전/문법 검사, 모든 띄어쓰기 |
| 법적·윤리적 위험 | 식별번호·휴대전화·이메일 형태, 혐의와 범행 단정의 병기, 일부 집단 낙인 패턴, 대상 입장 확인 질문 | 위법성, 면책, 보도 가능 여부 또는 법적 안전 보장 |
| 고유명사·인명·직책 | 사용자 표기 기준의 변형, 같은 이름의 다른 직책, 인용 화자 이름 차이 | 동명이인 식별, 현직 조회, 모든 기관명 자동 교정 |

원자료 비교는 **선택한 자료에서 문장당 최대 4개 검색 후보**에만 적용한다. 단어 유사성은 비교 후보를 고르는 조건이며 사실 확률이 아니다. ‘후보를 못 찾음’을 ‘근거가 없음’으로 표시하지 않는다. 제목은 본문과 비교하며, 인용·직책은 본문에서 찾은 후보도 참고한다. 제목만을 위한 별도 검색은 없다.

숫자는 조·억·만·천과 기본 단위를 정규화한다. `1억 2000만원` 같은 복합 표기는 판단을 유보한다. 변화율 규칙은 `100명에서 120명으로 30% 증가`처럼 제한된 형식에만 적용한다. 서로 다른 지표·기간을 완벽히 식별하지 못하므로 대조 문장을 함께 보여준다.

## 맞춤법 규칙과 수정 안전장치

`됬→됐`, `되요→돼요`, `몇일/몇 일→며칠`, `웬지→왠지`, `어의없→어이없`, `어떻해→어떡해`, 제한된 동사 뒤 `수 있/없` 띄어쓰기, `할것→할 것`의 8개 규칙이다. 어미·경계 조건은 코드의 SPELL_RULES에 정의한다.

본문 입력을 750ms 멈추면 밑줄 후보를 갱신한다. 제목의 후보는 점검 패널에서 확인한다. 자동으로 원고를 바꾸지 않으며 사용자가 개별 적용한다. 인용문 안은 수정 버튼을 주지 않고, 이름+직책에서 추출된 인명 및 등록한 표준명은 맞춤법 자동 수정 대상에서 제외한다. 미등록 고유명사를 모두 인식하는 것은 아니다.

적용 직전에 원고 버전과 해당 구간 텍스트를 다시 확인한다. 코드포인트 위치를 UTF-16 위치로 변환하므로 이모지가 앞에 있어도 다른 글자를 바꾸지 않는다. 마지막 적용은 되돌릴 수 있으며, 이후 수동 입력이 발생하면 해당 되돌리기는 폐기한다.

표기 기준 예: `국립국어원=국립국어언`. 표준명만 입력하면 보호어가 된다. 인명·기관명·직책 후보는 같은 대상을 가리키는지 확인 후 직접 수정한다.

## UX와 상태

- **우선 확인**: 구체적인 차이·계산 불일치·혐의 단정 등. 처음 3건만 보여주고 나머지를 펼친다. 순서는 제목/본문 위치 기준이며 위험 점수 순위가 아니다.
- **맞춤법·표기**: 오탈자와 사용자 표기 기준 차이. 적용·되돌리기와 원고 위치 이동을 제공한다.
- **추가 검토**: 인과 외삽 중 일반화 후보, 연락처, 직책, 대상 입장 질문 등 맥락이 필요한 항목.

각 항목은 위치, 이유, 다음 행동, 비교 원문이 있으면 그 위치를 제공한다. ‘확인함’은 기자가 검토했다는 상태다. 자동으로 사실 검증이 완료되었다는 의미가 아니다. ‘나중에’는 미처리 목록에 남으며 다시 열 수 있다. 이유 입력은 강제하지 않는다.

## 언제 끝났다고 표시하는가

1. **점검 실행 종료**: 현재 입력 전체가 제한 규칙 처리를 마치고 저장된 때다. `completion=check_finished`로 표현한다. 300문장/30,000자 초과는 일부 생략 대신 요청을 거부한다. 모델 실패·미평가는 별도 coverage에 남는다.
2. **표시 항목 처리**: 발견 항목을 사용자가 확인하거나 원고를 수정하고 재검사하면 진행 상황을 갱신한다. `acknowledged` 항목은 남은 수에서 제외한다. 재검사 결과에 과거 확인 상태를 자동 이월하지 않는다.
3. **송고 판단**: 기자와 편집 프로세스가 결정한다. API는 항상 `publication_blocked=false`이며 경고가 남아도 차단하지 않는다. 0건은 이번 규칙에서 발견한 항목이 없다는 뜻이다.

원고·제목·표기 기준·자료 선택·모델 설정이 바뀌면 이전 결과를 즉시 비운다. 자료 revision 변경, 늦은 응답, 수정 전 교정 버튼으로 현재 원고를 덮어쓰지 않게 검사한다. 서버의 input_hash는 본문·제목·자료 ID·표기 기준을 식별한다. 모델 설정은 클라이언트 버전과 별도 review_id로 구분한다.

## 평가와 다음 연결 지점

현재 자동 테스트는 규칙 동작, 정상 입력에서의 판단 유보, 출처 위치와 수정 안전을 확인한다. 실제 뉴스 데이터에서의 재현율·오탐률을 검증한 결과가 아니다. 팀의 맞춤법 엔진·검색·판정 모델을 연결할 때도 `Finding`, `CheckCoverage` 및 원문 위치 검증을 유지한다. 현 버전에는 외부 웹 검색, 완전한 한국어 교정 엔진, 법률 판정 모델을 연결하지 않았다.
