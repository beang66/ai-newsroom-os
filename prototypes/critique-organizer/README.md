# AI Newsroom OS — 기사 검토 보조·취재자료 탐색 v0.6

주 4~5건을 송고하는 기자를 위한 **7개 영역의 점검 보조와 취재자료 탐색 로컬 프로토타입**입니다. 구체적인 확인 후보를 제시하며 송고를 차단하지 않습니다. 외부 사실 확인이나 법적 판정을 수행하지 않습니다.

## 실행

Python 3.11 이상에서 ZIP을 풀고 `newsroom-module` 폴더로 이동합니다.

```bash
python -m pip install -r requirements.txt
python run.py
```

Windows에서 `python` 명령이 없다면 `py`로 바꿉니다. macOS/Linux에서는 `python3`를 사용할 수 있습니다. 실행하면 기본 브라우저를 열며, 직접 열 때는 http://127.0.0.1:8765 를 사용합니다. 종료는 터미널에서 Ctrl+C입니다. HTML만 더블클릭하거나 Live Server로 실행하면 API가 연결되지 않습니다.

`examples/source.txt`를 취재자료 탐색에서 업로드 → 기사 화면의 **비교 자료**에서 해당 파일 선택 → `examples/headline.txt`와 `examples/article.txt`를 제목·본문에 붙여넣기 → **송고 전 점검** 순서로 확인하세요. 예제는 가상 데이터이며 의도적인 오류가 있습니다. 비교 자료를 선택하지 않으면 기사 내부 규칙만 적용합니다.

## 자동 정리·3D Explore 추가

파일·폴더 가져오기, 규칙 기반 자료 유형/주제 분류, 원문 발췌, 취재 건 연결, 분류 수정·되돌리기, 검색·필터, 실패 원본 보관·재시도, STT JSON 연결을 제공합니다. 요청 시 OpenAI가 분류·발췌를 제안하며, 검토 후에만 적용합니다. 목록/3D가 같은 데이터를 사용하고 노드·연결선에서 근거 원문을 확인할 수 있습니다. 인물은 이름만으로 병합하지 않습니다.

요약은 **원문 발췌**이며 생성형 AI 서술 요약은 아닙니다. OpenAI는 제공된 원문 구간 중 최대 두 개를 선택할 수 있습니다. 3D는 안정된 공간 좌표를 Canvas에 투영한 탐색 화면입니다. 원본 파일을 이동하거나 재명명하지 않습니다. 상세 계약과 실행 시나리오는 [docs/ORGANIZER-v0.4.md](docs/ORGANIZER-v0.4.md)를 확인하세요.

## 실제 동작 범위

| 검사 영역 | 구현한 범위 |
|---|---|
| 사실관계 | 제목·본문 확정 수준, 자료와 날짜·부정 차이, 기사 내부 수량 차이 후보 |
| 숫자·통계 | 단순 단위·수치 비교, 증감률·%p·두 항목 합계 |
| 인용·출처 | 큰따옴표 인용 차이와 제한된 화자 비교 |
| 논리적 연결 | 명시적 인과 미확인 자료와의 충돌, 일부→전체 확대 후보 |
| 맞춤법·오탈자 | 입력 중 8개 기본 규칙. OpenAI 선택 후 송고 전 점검 시 추가 맞춤법 제안(최대 30건). 밑줄·개별 적용·한 단계 되돌리기 |
| 법적·윤리적 위험 | 개인정보 형태·혐의 단정·일부 낙인 표현·대상 입장 확인 질문 |
| 고유명사·인명·직책 | 사용자 표기 기준 및 같은 이름의 직책 차이 후보 |

우선 확인은 3건부터 보여주며, 맞춤법·표기와 추가 검토를 나눕니다. ‘확인함/나중에/다시 열기’ 상태를 저장하고 입력이 바뀌면 이전 결과를 무효화합니다. 확인함은 사실 확정이 아닙니다. 상세 조건과 완료 기준은 [docs/CRITIQUE-v0.3.md](docs/CRITIQUE-v0.3.md)에 있습니다.

기본 검사는 **제한된 규칙**입니다. OpenAI 맞춤법은 제안이며 전체 한국어 맞춤법의 완전성을 보장하지 않습니다. 그 외 실시간 사실 조회, 법률 심사 또는 포괄적인 논리·편향·문체 검사는 구현하지 않았습니다. 자료 검색은 키워드 후보 검색이며 임베딩/RAG 생성은 없습니다. 원본 바이트·SHA-256·블록 위치를 저장하고 비교 발췌를 정확히 강조합니다. 파서가 읽지 못한 영역은 원본에서 확인해야 합니다.

PDF·DOCX·XLSX는 파서가 처리한 범위와 제외 영역을 화면에 표시합니다. 최대 파일 10MB, 추출 텍스트 30만 자/5,000블록, PDF 100페이지, XLSX 10시트·시트당 1,000행/100열입니다. 한도 초과는 파일 전체를 거부하고 이유를 보여줍니다. TXT/MD/CSV/JSON은 UTF-8 텍스트로 읽으며 CSV/JSON 구조 해석은 하지 않습니다. 스캔 PDF OCR·STT·영상 분석은 없습니다.

지도는 전체 노드 수와 표시 수를 함께 알리고 기본 60개·최대 150개 노드를 표시합니다. 3D 좌표는 가독성을 위한 구면 배치이며 관계 강도·의미 유사도가 아닙니다.

## OpenAI API 키 설정

ZIP을 푼 뒤 `newsroom-module` 폴더에서 `.env.example`을 **`.env`로 복사**합니다. macOS/Linux는 `cp .env.example .env`, Windows PowerShell은 `Copy-Item .env.example .env`를 실행하세요. 그 `.env` 파일의 `OPENAI_API_KEY=` 오른쪽에 발급받은 키를 적습니다. 예: `OPENAI_API_KEY=발급받은_실제_API_키`. `OPENAI_MODEL` 기본값은 `gpt-5.4-mini`입니다. 저장하고 `python run.py`를 다시 실행하세요. 이미 설정된 서버 환경 변수는 `.env`보다 우선합니다.

키는 서버에서만 읽습니다. `.env`는 배포 ZIP과 소스 관리에서 제외하고 `.env.example`, HTML/JS, 채팅에는 실제 키를 넣지 마세요. 팀 서비스에서는 배포 환경의 비밀 환경 변수 `OPENAI_API_KEY`를 사용하세요. ChatGPT 이용권과 API 사용량 청구는 별개입니다.

기본은 로컬 검토입니다. 왼쪽 **API 연결 확인** 버튼은 원고를 전송하지 않는 최소 요청으로 실제 연결을 확인하며 API 사용량이 발생할 수 있습니다. 키만 등록했을 때의 ‘연결 미확인’은 정상 상태입니다. 실패 시 키·모델·사용 한도·네트워크 오류의 분류가 표시됩니다. **OpenAI 사용**을 체크하고 **송고 전 점검**을 누르면 제목·본문 전체의 맞춤법 제안과 선택 자료의 검색 후보 발췌 비교를 요청합니다. 예를 들어 `오늘 회의가 잇었습니다.`는 기본 8개 규칙 밖이므로 AI 검사를 선택해야 합니다. 결과는 **맞춤법·표기** 탭과 원고 밑줄에서 확인하고 개별 적용하세요. AI 호출 실패 때는 실패 상태를 표시하고 기본 8개 규칙만 남습니다. 자료 상세의 **OpenAI 분류·발췌 제안 받기**를 누르면 해당 문서의 앞 12블록에서 각 500자, 합계 최대 6,000자를 전송합니다. 제안은 검토 후 적용할 때만 저장됩니다. 키 설정 여부와 실제 요청 성공 여부는 다릅니다. 모델의 `supports`는 발췌와의 관계 판단일 뿐 사실 확정이 아닙니다. confidence 수치를 사실 신뢰도로 표시하지 않습니다.

문서 속 지시문 형태를 규칙으로 일부 탐지하면 모델 평가를 막습니다. 이 탐지기나 프롬프트만으로 프롬프트 인젝션 방어가 완성되었다고 주장하지 않습니다. 모델에는 도구 실행·파일 이동·자동 승인 권한이 없습니다.

## 팀 코드에 합치기

[팀 저장소 인계 메모](docs/TEAM-HANDOFF.md)에 독립 폴더로 올리는 방법, 파일별 책임과 알려진 맞춤법 누락을 적었습니다. 팀의 기본 브랜치에는 바로 합치지 않고 기능 브랜치에서 리뷰하세요.

[docs/INTEGRATION.md](docs/INTEGRATION.md)에 역할별 연결 지점, API, 기존 DB 처리, 삭제 정책을 정리했습니다. 프런트 계약은 [docs/contracts.d.ts](docs/contracts.d.ts), Python 인터페이스는 `app/contracts.py`입니다. `review.py`는 DB와 외부 모델을 직접 import하지 않습니다.

원고는 같은 브라우저 탭의 sessionStorage에 임시 저장됩니다. API 검토 결과에는 원고 버전·해시를 기록합니다. 원고를 수정하면 이전 결과를 지우며 늦게 도착한 응답은 버립니다. 사용자별 로그인이나 영구 초안 관리 서비스는 포함하지 않았습니다.
