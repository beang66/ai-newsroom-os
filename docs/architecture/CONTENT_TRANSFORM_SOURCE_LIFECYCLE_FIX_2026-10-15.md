# 콘텐츠 변환 원문·결과 연결 및 형식 복구 수정

작업 브랜치: `feature/platform-generator`. 작업 시작 시 존재한 미커밋 변경과 신규 파일을 보존했다. 이번 작업에서 커밋·push·PR·게시·실제 AI 호출은 실행하지 않았다. Core/Python 및 App.jsx는 수정하지 않았다.

## 확인된 문제와 수정

1. HTML/일반 텍스트를 그대로 비교하던 적용 오류: 기존 `plainContent`를 비교용 `sourceText`와 편집실 조회에 재사용한다. 저장 원문·사진·근거 인용을 고쳐 쓰지 않는다. 제목·부제·URL 및 원문 변경의 기존 차단은 유지한다.
2. 다른 기사 복원 시 플랫폼 필드가 없으면 이전 기사의 값을 물려받던 문제: `editorialStore.js`에 플랫폼 필드 기본값 세 개를 명시한다. 실제 저장된 플랫폼 데이터·미지원 과거 기록은 유지한다. 저장 정책·DB 스키마·Core 계약은 바꾸지 않는다.
3. 같은 기사 ID의 이전 원고가 새 생성 실패와 함께 표시되던 문제: 결과마다 현재 원문/이전 원문을 표시한다. 이전 원고는 삭제하지 않으며, 현재 원문용 검수·SNS 입력에서 제외한다.
4. 입력 조건: 비교용 원문 버전 키를 플랫폼 설정에 저장한다. 이전 원문 또는 연결 불명의 레거시 키워드·추가 요청은 보관하고 현재 생성에 자동 적용하지 않는다. 명시적인 확인 버튼으로 재사용할 수 있다. 사진 변경만으로 조건을 지우지는 않는다.
5. 생성 작업: 기사 ID·원문·조건을 각 호출 전과 응답 후에 확인한다. 기사 전환 중이거나 원문/조건이 바뀌면 후속 호출과 적용을 중단한다. 성공한 다른 플랫폼과 사용자가 편집한 결과는 보존한다. 늦은 응답을 다른 기사에 자동 저장하지 않는다.
6. 상태: 텍스트 플랫폼의 `완료`를 `초안 생성 완료 · 검수 별도`로 표시한다. JPG는 `카드 JPG 준비 완료`로 표시하고 검수·SNS 입력과 별도임을 명시한다. JPG 단계 실패를 문안 생성 실패로 오인하지 않게 구분한다.
7. SNS: 현재 원문이라도 원고·카드 고정본이 다르면 사전 안내한다. Core의 동일 고정본·이미지 최신성 검사는 유지한다. 명시적인 근거 불일치 결과도 SNS 입력에서 차단한다. Threads 카드 없는 준비는 유지한다.
8. 추적: 새 작업부터 작업 식별자·시각·플랫폼·기사/고정본·단계·상태·안전한 오류 코드를 최대 20건 보관한다. 원문·AI 응답·키·계정 값이나 JSON fingerprint는 기록하지 않는다. `generation_run` 메타데이터만 추가된 경우 기존 검수를 무효화하지 않는다. 과거 실패에 새 작업 ID를 소급해서 붙이지 않는다.

## 제한적인 형식 복구

- Instagram 문장 끝의 닫는 따옴표는 판정에서만 제외하며 실제 문안은 유지한다.
- 해시태그 구분자·공백·중복을 정리한다. 여전히 3~5개 형식을 충족하지 못하면 해시태그 필드만 한 번 보완한다. 기존 문체 교정과 합쳐 생성/보완 요청은 총 2회를 넘기지 않는다. 정상 경로에는 추가 호출이 없다.
- 잘못된 교정 JSON의 내용을 오류 메시지에 노출하지 않는다.
- AI가 새로 생성한 본문 비교형만 항목 수가 맞지 않으면 설명형으로 바꾼다. 문안·근거·주요 정보 배분·표지·마지막 카드는 유지하고 기존 구조/의미 검수를 계속한다. 저장본·사용자 편집본에는 이 자동 복구 함수를 사용하지 않는다.
- 사실·근거·누락 검사는 완화하지 않았다. 긴 문안의 삭제·과도한 축소·자동 카드 분할도 추가하지 않았다.

## 검증

- `npm test`: 58개 통과, API 경계 검사 포함.
- 카드뉴스·Instagram 작성·생성 복구 테스트: 47개 통과. 해시태그 필드만 보완, 추가 호출 없음/최대 2회, 잘못된 교정 JSON 비노출, 자동 비교형 복구와 문안·근거 보존 포함.
- React 화면 테스트: 3개 통과. 실제 복원 함수 사용, HTML 적용, 같은 ID 원문 교체, 이전 조건 격리·재사용, 새로고침 복원, 일부 실패와 단일 재시도, 같은 ID/다른 ID 전환 후 늦은 응답 차단, SNS 두 버튼 및 같은 원문/다른 고정본 거부, JPG 수정 카드만 재확인·정상 이미지 재사용 포함.
- `npm run build` 통과. 기존 editorial.js 동적/정적 import 중복 경고가 남아 있다.
- 대상 lint는 오류 없이 종료했으며 React ref/effect/immutability/purity 경고는 남아 있다. 경고를 없애기 위한 광범위한 공통 화면 리팩터링은 하지 않았다.
- 실제 앱에서 저장 기사 목록의 현재 계란 기사를 다시 조회·선택·적용했고 적용 실패가 없었다. 이전 반도체 Instagram 원고가 보존본으로 표시되고 SNS 준비가 차단됨을 확인했다. 계란 Threads는 현재 원문·미검수, 카드 JPG는 5/5 준비로 각각 표시됨을 확인했다. 기존 원고·카드 삭제 및 새 AI 생성·게시를 실행하지 않았다.

## 남은 범위

- 실제 AI 새 생성 품질과 실제 SNS 첨부·원고 입력은 이번 작업에서 검증하지 않았다. 모의 시험을 실제 AI 품질 검증으로 해석하지 않는다.
- 실제 계정 전환은 실행하지 않았다. 계정별 백업 자동 테스트는 통과했으나 앱 전체 계정 전환 동작을 새로 구현/검증한 것은 아니다.
- URL은 없어도 생성할 수 있지만 명시적으로 입력된 잘못된 URL의 기존 거부는 유지한다. URL·부제만 바뀔 때의 원문 최신성 정책도 이번에 완화하지 않았다.
- 원문이 같아도 다른 고정본의 원고·이미지를 함께 SNS에 보내는 것은 기존 계약상 허용하지 않는다. 이전 결과의 고정본 ID를 변경해 우회하지 않는다.
- 사소한 배치 복구 후에도 실제 JPG가 넘치면 편집이 필요하다. 잘린 이미지나 근거 오류를 성공 처리하지 않는다.
