# 콘텐츠 변환: 문맥 보조·중복 검수 감소 변경 기록

작성일: 2026-10-14 (Asia/Seoul)

## 사용자 요청과 이번 적용 범위

플랫폼별 전체 원문·규칙·품질 검수를 유지하면서 현재 방법을 적용하고 불필요한 재검수를 줄이라는 요청에 따라, **임베딩 없는 원문 위치 기반 문맥 보조(B0)와 동일 결과의 검수 재사용**을 구현했다. 팀원에게 메시지를 보내거나 커밋·푸시·배포하지 않았다. 이 문서는 팀 공유용 기록이다.

Core 의미 검색(B1), 고정본 검색 색인, 새 임베딩 호출, 새로운 Core API/IPC/DB 계약은 구현하지 않았다. OpenAI 모델·키·백엔드 설정과 `platform-rules.js`도 변경하지 않았다.

## 변경된 행동

### 1. 인용 위치 기반 주변 문맥 안내

- 새 `platform-generator/lib/quote-context.js`가 검수 대상의 `source_evidence`/`block_evidence`를 원문 본문에서 찾는다.
- 공백·CRLF를 정규화해 찾되 원문 UTF-16 좌표로 역매핑하고 실제 원문 구절을 반환한다. 반복된 인용은 발생 위치를 보존한다.
- 해당 문단과 앞뒤 문단을 `evidence_context`로 현재 두 검수 요청에 함께 제공한다. 전체 원문·결과·규칙과 사실→편집/요구사항 검수 순서는 유지한다.
- 추가 임베딩·LLM 요청은 없다. 최대 24발생 위치/6,000자 문맥 예산을 적용하고 잘라낸 인용 대신 `context_complete=false`를 표시한다. 예산이 있다는 이유로 전체 원문을 축소하지 않는다.
- 없는 인용은 `unmatched`로 남으며 유사 구절로 교체하지 않는다. 제목의 인용은 기존 존재 검사를 유지하지만 본문 문맥을 찾은 것으로 표시하지 않는다.
- 문맥을 추가하므로 입력 토큰이 늘 수 있다. 문맥 보조 자체의 품질·시간 개선은 실계정으로 아직 측정하지 않았다.

### 2. 새 카드뉴스 생성 중 검수 결과 재사용

- `draft-validator.js`는 실제로 검수한 전체 원문·키워드·요구사항·플랫폼 규칙·정규화된 검수 대상·문맥 버전의 SHA-256 `review_context`를 반환한다.
- `card-news-generator.js`는 최종 반환 카드의 검수 입력과 위 해시가 같은 경우에만 `generation_review_binding`을 추가한다. 구조 검사만 수행한 결과, 실제 의미 검수와 다른 최종 출력은 연결하지 않는다.
- 연결 정보에는 원문/출력 SHA-256만 담아 원문·규칙·카드 문자열을 추가 복사하지 않는다. 생성 중 수정이 있었다면 마지막 실제 검수의 입력과 비교한다.
- 프론트 API는 **이번 생성 응답**의 결합을 확인한 뒤 검수 결과를 `validation_review`에 연결한다. 예전 저장본의 `generation_review`를 자동 승격하지 않는다.
- 통과뿐 아니라 `needs_revision` 결과도 그대로 표시한다. 오류가 있는 결과를 통과로 바꾸지 않는다.
- 조건이 맞는 새 카드뉴스는 이미 완료된 사실/편집 검수 2회를 다시 요청하지 않아 정상 경로에서 생성·검수 LLM 요청이 기존 6회에서 4회로 줄어드는 구조다. 옵션 키워드·사진·재시도는 이 수에 포함하지 않는다. 이는 모의 호출 검증 결과이며 실제 시간 절감률이 아니다.

### 3. 같은 작업 화면의 중복 검수 방지

- `PlatformReview`는 같은 현재 런타임에서 완료된 원고·플랫폼·원문·사진·조건의 검수를 재호출하지 않는다.
- 해당 버튼은 ‘검수 완료’로 표시하고, 사용자가 원하면 ‘다시 검수’로 실제 API를 호출할 수 있다. 중복 클릭 중 동시 요청도 차단한다.
- 카드/원고·원문·제작 조건·사진 변경 또는 명시적 재검수 필요 상태는 재사용을 무효화한다.
- 재사용 표시의 런타임 참조는 JSON 저장·복원 후 동일하지 않으므로 저장본 복원이나 앱 재시작 후에는 재검수를 생략하지 않는다. 실제 검수 상태의 기존 저장/표시 기능은 유지한다.
- 서버 모델/규칙이 실행 중 교체되는 경우 이를 자동으로 조회하는 새 Core 계약은 없다. 다시 검수 또는 앱 재시작으로 재검사할 수 있다. 이번에 모델/규칙을 교체하지 않았으며 서버 버전 간 영구 캐시로 구현한 것은 아니다.

## 변경 파일과 팀 경계

| 파일 | 변경 |
| --- | --- |
| `platform-generator/lib/quote-context.js` | 구절 위치·문맥 조립 |
| `platform-generator/lib/review-binding.js` | 새 응답의 원문·출력 결합 확인, 브라우저 Web Crypto 비교 |
| `platform-generator/draft-validator.js` | 보조 문맥 입력·검수 입력 해시 |

| `src/api/platform.js` | 결합이 확인된 새 생성 응답만 화면 검수 결과로 연결 |
| `src/lib/platformState.js` | 검수 재사용 조건·런타임 한정 |
| `src/components/PlatformReview.jsx` | 중복 호출 방지·명시적 다시 검수 |
| `platform-generator/tests/quote-context.test.cjs` | 문맥 매핑·오류 보존·실제 생성 호출·결합 회귀 |
| `article_editor/dev/tests/platform-state.test.mjs` | 변경/복원 무효화·API 어댑터 회귀 |

기존 Core Python 코드·자료 검색 알고리즘·고정본 스키마·`src/api/core-api.js` 라우트는 변경하지 않았다. 기존 `/api/platform/generate`·`validate` 경로를 사용하며 Node 결과에 관찰/연결 필드가 추가된다. 팀은 이 부가 필드와 후속 저장 형식을 검토할 수 있다. 배포 빌드는 기존 설정으로 `article_editor/app/frontend/`를 재생성했으며 EXE 재패키징은 하지 않았다.

## 검증 결과

- 루트 `npm test`: 47개 통과, 실패/skip 0. API-boundary 검사 통과.
- 문맥·검수 연결·상태·기존 Instagram/Threads 작성 기준 대상 검사: 19개 통과, 실패/skip 0. API는 대역이며 실제 과금 호출 없음.
- 카드 생성 회귀는 배분표 1회·작성 1회·사실/편집 검수 2회의 총 4회를 확인하고, 최종 카드·원문·조건 변경 시 연결 해제가 되는지 확인했다.
- `npm run build`: 통과. 기존 `editorial.js` 정적/동적 import 경고는 남아 있다.
- 변경 코드의 oxlint: 오류 없이 완료. 기존 검수 프롬프트의 불필요 escape와 기존 미사용 변수 경고가 남아 있으며 작성 규칙은 정리 작업으로 바꾸지 않았다.
- 운영 AI 품질·토큰·기사 선택부터 완료까지의 시간, 전체 플랫폼 서버/브라우저/SNS 검사, 실계정·운영 DB·EXE 실행은 이번에 미검증이다. 생성기 전용 외부 의존성이 이 작업 환경에 설치돼 있지 않아 전체 플랫폼 서버 검사를 실행한 것으로 표시하지 않는다.

## 기존 실험안과의 관계

[실험안](../architecture/CONTENT_TRANSFORM_SEARCH_EXPERIMENT_2026-10-14.md)과 [별도 계약 초안](../architecture/CONTENT_TRANSFORM_SEARCH_CONTRACT_PROPOSAL_2026-10-14.md)은 사전 설계 기록으로 유지한다. 이번 제품 적용은 B0 + 중복 재호출 감소를 함께 포함한다. 이후 검색/문맥의 순수 효과 비교에서는 A/B0/B1에 같은 검수 재사용 정책을 적용하거나 각각 분리해 비교해야 한다. 이번 4회 호출 확인을 B1의 효과나 원문 문맥 보조의 속도 효과로 해석하지 않는다.

다음 실제 평가는 플랫폼별 사실·핵심 누락·오탐·사람 수정량과 토큰/전체 시간을 측정한다. 숫자로 품질·속도 개선을 주장하기 전까지 문맥 보조의 운영 효과는 검증 대기다.
