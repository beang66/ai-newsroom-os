# 보관함 탐색기 개편 계획

## 1. 목표

보관함을 기사 목록이 아니라 기사·취재 자료·음성·사진·카드뉴스를 한곳에서 찾는 통합 파일 탐색기로 만든다. Windows 파일 탐색기의 익숙한 조작 방식을 따르되 실제 파일을 임의의 디스크 폴더로 옮기지 않고, 현재 계정별 암호화 저장소 안에서 가상 폴더·태그·상태를 관리한다.

## 2. 분류 원칙

`원고 / 송고`는 파일 종류가 아니라 기사 처리 상태이므로 최상위 폴더로 사용하지 않는다.

### 빠른 접근

- 모든 파일
- 최근 사용
- 즐겨찾기
- 내가 만든 파일

### 종류별

- 기사
- 취재 자료
- 음성·녹취
- 사진
- 카드뉴스
- 내보낸 파일

### 날짜별

- 오늘
- 최근 7일
- 이번 달
- 연도 / 월

### 관리

- 태그
- 사용자 폴더
- 휴지통

기사의 `작업 중`, `검토 필요`, `송고 완료`, `송고 후 수정`은 폴더가 아닌 상태 필터로 제공한다. 상태를 바꿔도 파일 위치가 바뀌지 않아 사용자가 파일을 잃어버렸다고 느끼지 않게 한다.

## 3. 화면 구조

### 상단 도구 모음

- 전체 자료 통합 검색
- 새 폴더, 즐겨찾기, 이동, 삭제
- 이름·수정일·종류·상태·크기 정렬
- 자세히 보기, 작은 아이콘, 큰 아이콘 전환
- 현재 검색과 필터 초기화

보기 방식과 열 너비는 사용자별 화면 설정으로 기억한다.

### 왼쪽 탐색 영역

- 빠른 접근, 종류별, 날짜별, 태그, 사용자 폴더, 휴지통을 접을 수 있는 트리로 표시한다.
- 각 항목 오른쪽에 현재 파일 개수를 표시한다.
- `작업 중`, `검토 필요`, `송고 완료`는 상태 필터 칩으로 제공한다.
- 자료를 사용자 폴더나 태그 위로 끌면 실제 파일 이동 대신 분류 정보만 추가한다.

### 가운데 자료 목록

기본 보기는 자세히 보기이며 다음 열을 제공한다.

| 열 | 내용 |
| --- | --- |
| 이름 | 기사 제목 또는 파일명 |
| 종류 | 기사, 취재 자료, 음성, 사진, 카드뉴스 등 |
| 담당자 | 생성자 또는 기사 담당자 |
| 수정일 | 마지막 저장·수정 시각 |
| 상태 | 작업 중, 검토 필요, 송고 완료 등 |
| 연결 자료 | 기사에 연결된 취재 자료 수 |
| 태그 | 사용자가 지정한 분류 |

- 한 번 클릭은 선택과 미리보기, 두 번 클릭은 기본 편집 화면 열기로 동작한다.
- `Ctrl+A`, `Shift+클릭`, `Ctrl+클릭`으로 다중 선택한다.
- `Delete`는 휴지통 이동, `Enter`는 열기, `F2`는 표시 이름 변경으로 동작한다.
- 목록의 빈 공간을 눌러 선택을 해제하며, 삭제 후에는 다음 항목을 선택한다.
- 남은 항목이 없으면 현재 폴더명과 함께 명확한 빈 상태 안내를 표시한다.

### 오른쪽 미리보기 영역

선택한 종류에 맞는 미리보기를 제공한다.

- 기사: 제목·부제·본문 일부·상태·연결 자료와 `열기`, `데이터맵`, `삭제`
- 취재 자료: 파일 정보·추출 본문·연결 기사와 `원본 보기`, `기사에 연결`
- 음성·녹취: 재생 정보·녹취 일부·화자와 `전사 열기`
- 사진: 썸네일·설명·출처·사용 기사와 `편집`, `기사에 넣기`
- 카드뉴스: 카드 썸네일·기준 기사·생성 시각과 `편집`, `내보내기`

미리보기 영역은 접을 수 있고, 좁은 화면에서는 목록 아래에 배치한다.

## 4. 검색 계획

검색창은 현재 폴더뿐 아니라 보관함의 모든 자료를 기본 대상으로 한다.

검색 대상:

- 기사 제목·부제·본문
- 취재 자료 파일명·추출 본문
- 음성 파일명·녹취·화자명
- 사진 설명·출처·파일명
- 카드뉴스 제목·카드 문구
- 담당자·태그·사용자 폴더명

검색 결과에는 일치한 위치와 자료 종류를 표시하고 `종류`, `수정일`, `담당자`, `상태`, `태그`로 결과를 좁힌다. 1차 구현은 현재 암호화 DB의 통합 읽기 모델과 정규화된 부분 검색을 사용하고, 자료가 많아질 때 FTS 인덱스를 추가한다.

## 5. 탐색기식 동작

- 우클릭 메뉴: 열기, 새 창에서 열기, 즐겨찾기, 폴더로 분류, 태그, 데이터맵, 이름 변경, 휴지통 이동, 정보
- 드래그: 사용자 폴더·태그 지정, 기사 위에 자료를 놓아 연결, 휴지통 위에 놓아 삭제 확인
- 다중 선택 작업: 이동, 태그 추가·제거, 즐겨찾기, 삭제
- 정렬: 오름차순·내림차순과 폴더 우선 표시
- 선택 유지: 정렬·보기 방식 변경 후에도 같은 항목 유지
- 삭제 후 선택: 삭제한 위치의 다음 항목, 없으면 이전 항목, 목록이 비면 빈 상태 표시

브라우저 밖으로 파일을 끌어내는 동작은 내보내기로 처리하며 암호화 저장소의 내부 경로를 노출하지 않는다.

## 6. 데이터와 API 구조

기존 기사·자료·녹취·미디어·카드뉴스 저장 테이블은 유지하고, 보관함 전용 통합 읽기 모델을 추가한다.

### 통합 항목 모델

```text
LibraryItem
- id
- type: article | source | audio | photo | card | export
- title
- owner
- updatedAt
- createdAt
- status
- size
- tags[]
- folderIds[]
- favorite
- deletedAt
- preview
- relationCounts
```

### 추가 저장 정보

- `library_folders`: 사용자 폴더 이름과 상위 폴더
- `library_folder_items`: 항목과 폴더 연결
- `library_tags`: 태그 정의
- `library_item_tags`: 항목과 태그 연결
- `library_favorites`: 사용자별 즐겨찾기
- 보기 방식·정렬·열 너비는 로컬 화면 설정에 저장

### API

- `GET /api/library`: 검색·종류·상태·날짜·태그·폴더·정렬·페이지 조회
- `GET /api/library/:type/:id`: 종류별 미리보기
- `POST /api/library/folders`: 사용자 폴더 생성
- `PATCH /api/library/items`: 폴더·태그·즐겨찾기 일괄 변경
- `POST /api/library/trash`: 여러 항목 휴지통 이동
- `POST /api/library/restore`: 여러 항목 복원

기존 기사 API와 데이터맵 API는 유지하고 통합 읽기 모델이 같은 ID를 참조하게 한다.

## 7. 구현 순서

1. 모든 화면의 기능명을 `보관함`으로 통일한다.
2. 통합 `LibraryItem` 읽기 모델과 전체 자료 검색 API를 만든다.
3. 세 영역 레이아웃과 자세히 보기 목록을 적용한다.
4. 종류·날짜·상태·태그 필터와 보기 방식 전환을 추가한다.
5. 종류별 미리보기와 열기·데이터맵·삭제 동작을 연결한다.
6. 다중 선택, 키보드, 우클릭 메뉴를 추가한다.
7. 사용자 폴더·태그·즐겨찾기와 드래그 분류를 추가한다.
8. 휴지통 복원, 삭제 후 다음 항목 선택, 빈 상태를 검증한다.
9. 자료 규모를 측정한 뒤 필요하면 전문 검색 인덱스를 적용한다.

## 8. 완료 기준

- 기사·취재 자료·음성·사진·카드뉴스가 한 검색창에서 검색된다.
- 최상위 분류가 `원고 / 송고`가 아니라 빠른 접근·종류·날짜·사용자 폴더로 구성된다.
- 상태 변경 때문에 항목의 폴더 위치가 바뀌지 않는다.
- 세 가지 보기 방식과 정렬 결과가 다시 열어도 유지된다.
- 다중 선택, `Ctrl+A`, `Delete`, 우클릭, 드래그 분류가 동작한다.
- 삭제 후 화면이 사라지지 않고 다음 항목 또는 빈 상태가 표시된다.
- 보관함과 데이터맵이 동일한 기사·자료 ID와 관계를 표시한다.
