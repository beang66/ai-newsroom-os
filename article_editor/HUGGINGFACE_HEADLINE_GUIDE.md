# AI 핵심 각도 + KeT5 헤드라인 기능

## 현재 서비스 구조

코랩은 사용하지 않는다. 실제 기사 작성 화면에서 다음 순서로 제목을 생성한다.

1. OpenAI API가 기사 전체에서 가장 새롭고 구체적인 핵심 각도를 선택한다.
2. API가 핵심 표현, 원문 근거, 제목 모델용 압축 문장을 만든다.
3. 로컬 `onebeans/keT5-news-title-gen` 모델이 뉴스 제목 초안 10개를 생성한다.
4. `gogamza/kobart-summarization`이 중요도가 충분한 서로 다른 원문 근거 1~3개를 각각 부제 초안으로 압축한다.
5. AI 편집 데스크가 제목·부제 초안을 원문과 대조하고 띄어쓰기·길이·약칭을 교열한다.
6. 부제마다 대상·행동·결과가 모두 남고 명사형으로 끝나는지 검사한다.
7. 화면에 핵심 각도, 제목 후보 3개, 필요한 만큼의 부제 1~3줄과 각각의 원문 근거를 표시한다.
8. 사용자가 후보를 누르면 제목란과 기사 미리보기에 바로 적용된다.

제목 후보의 순서와 역할 이름은 유지하되, 아래 설명은 강제 형식이 아니라 서로 다른 선택지를 만들기 위한 편집 방향으로 사용한다. 자연스러운 제목과 기사 맥락을 우선하며, 모든 핵심어를 세 후보에 똑같이 반복하지 않는다.

1. 정석형: 가장 중요한 사실을 곧바로 전달한다. 핵심 각도의 새 사실을 빠뜨리지 않는다.
2. 행위·결과형: 무엇을 하면 어떤 처분을 받는지 강조한다. 사건·사고 기사는 어떤 행동이 어떤 결과(피해·조치)로 이어졌는지 보여 준다.
3. 수치·충격형: 2년·5년, 7㎞처럼 눈에 띄는 수치를 강조한다. 원문에 없는 과장은 하지 않는다.

부제는 제목의 핵심을 보충한다. 경위·원인·직접 결과와 피해를 우선하고, 수사 예정 같은 후속 절차는 다른 보충 사실이 없을 때만 쓴다.

제목에서 대등한 항목을 압축해 나열할 때는 `·`을 사용하고, 앞부분의 화제·조건과 뒤의 결과를 나누면 더 잘 읽히는 경우에는 `,`를 사용할 수 있다. 공백으로 명사를 길게 이어 붙이는 표현은 피하되, 문장부호를 모든 제목에 강제하지 않는다.

## 이 구조를 선택한 이유

- KeT5는 AIHub 신문기사로 제목 생성을 학습한 모델이어서 뉴스 제목 모델이라는 근거가 있다.
- KeT5는 지시형 모델이 아니므로 긴 프롬프트를 직접 전달하지 않는다.
- API는 제목을 바로 쓰는 역할보다 기사 각도와 근거를 찾는 편집 데스크 역할을 맡는다.
- 부제는 개수를 채우지 않고, 제목을 보충할 중요 사실이 있을 때만 1~3개의 서로 다른 근거 문장을 `대상 + 행동 + 결과` 구조로 압축한다.
- KoBART 출력은 근거별 초안으로만 사용하고, AI 편집 데스크가 기사 핵심 주체를 넣어 20~36자의 부제로 다시 압축한다.
- `시험 중 활용하면`처럼 대상을 생략하지 않고 원문의 `AI 기기` 같은 핵심 명사를 각 부제에 남긴다.
- 각 부제는 `정지`, `제한`, `허용`, `도입`, `추진` 같은 명사형으로 끝낸다.
- 기사 전체가 KeT5의 512토큰 한도를 넘더라도 핵심 문장을 앞에 배치한 압축 입력을 사용한다.
- 기사에 공식 영문 약칭이 괄호로 제시되면 코드가 이를 찾아 제목 표기를 통일한다.

## 화면에서 확인할 수 있는 정보

- AI가 잡은 핵심 각도
- KeT5 초안과 AI 데스크 교열을 거친 제목 후보 3개
- 제목 판단에 사용된 원문 근거 문장
- 후보 선택 시 즉시 갱신되는 기사 미리보기

## 실행 환경

OpenAI API 설정 외에 `requirements-headline.txt`(onnxruntime·tokenizers)와 ONNX 변환 모델(`models/headline-ket5-onnx`, `models/subtitle-kobart-onnx`)이 필요하다. 2026-10-02부터 KeT5·KoBART 는 transformers 대신 ONNX 로 실행하며, 원본 generate 와 후보 문장이 같다(검증: `dev/tools/convert_seq2seq_onnx.py --parity`). 모델은 서버가 실행되는 동안 메모리에 한 번만 올리고 이후 요청에서 재사용한다.
