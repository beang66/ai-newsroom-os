# 카드뉴스 JPG 준비 상태와 3번 카드 렌더 실패 수정

## 실제 실패 원인 및 측정

Chrome의 기존 콘텐츠 변환 화면에서 실제 실패한 3번 카드를 선택해 측정했다. 기사 원문·계정·키·사진 바이트는 이 문서에 기록하지 않는다.

| 측정 | 수정 전 | 수정 후 |
|---|---:|---:|
| 카드 크기 | 1080 × 1350 | 동일 |
| 글 영역 시작 / 허용 높이 | 154 / 1056px | 동일 |
| 상세 설명 끝 | 1219.421875px | 1196.421875px |
| 글 영역 경계 | 1210px | 동일 |
| 글 영역 scrollHeight | 1065px | 1056px |
| 상세 글자 크기 | 37px | 동일 |
| 텍스트 이동값 | 모두 0 | 동일 |
| 겹침 / 넘침 | 없음 / 있음 | 없음 / 없음 |

목록의 마지막 항목에도 남은 하단 padding 22px + 구분선 1px가 높이를 늘렸다. 마지막 항목의 이 두 장식만 제거했다. 글꼴·문안·줄바꿈·카드 수·정보 배분·텍스트 위치는 수정하지 않았다. 실물 JPG와 편집 미리보기의 템플릿·1080×1350 크기·글꼴·줄바꿈 측정이 일치함을 확인했다. 미리보기도 JPG와 같이 글꼴·사진 로딩 후 측정하고 넘침 결과를 표시한다.

## 상태와 호출 경로

- 문안 생성 완료 후 `PlatformStudio`에서 기존 `renderStoredCard → Core render → MediaAsset` 경로로 전체 카드를 확인한다. 문안 상태와 `카드뉴스 업로드 준비 완료`를 구분한다.
- 후자는 모든 카드의 현재 key·기사 ID·고정본 ID가 일치하는 보관 JPG가 있을 때만 표시한다.
- 공통 준비 함수는 성공 이미지를 즉시 적용하고 한 장이 실패해도 나머지를 확인한다. 실패 번호·이유는 카드 메타데이터로 보존하며, 현재 카드 key에 해당하는 오류만 표시한다.
- 문안·사진·디자인·위치 편집은 자동 렌더를 일으키지 않는다. `JPG 준비 확인` 또는 SNS 작성창 준비 직전에 변경 카드만 다시 렌더한다. 정상 이미지는 재사용한다.
- 전체 성공 때만 순서가 있는 assets를 반환한다. 부분 SNS 첨부 금지와 Core의 소유권·고정본 검사, 기존 사진 저장 경계를 유지한다.
- 렌더 메타데이터는 기존 문안 검수를 무효화하지 않는다. 새 AI 단계나 사실 검수 재호출을 추가하지 않았다.

## 실제 앱 확인

기존 카드는 다시 생성하지 않았다. 기존 정상 JPG 2장을 재사용하고 3·4번 카드만 Core로 새로 렌더·보관했다. 전체 4/4장 준비 완료까지 2.8초가 걸렸다. 같은 상태에서 재확인했을 때 새 렌더 0장·재사용 4장, 화면 집계 0.0초였다. 1~4번 카드를 차례대로 열어 Core 자산 네 장이 모두 1080×1350 이미지로 정상 로딩됨을 확인했다. 실제 Instagram 작성창 준비·게시·송고는 실행하지 않았다.

## 이번 수정 파일

- `platform-generator/lib/card-template.js`, `card-renderer.js`: 목록 끝 장식 수정, 필드별 넘침 계측·오류 안내.
- `src/components/PlatformStudio.jsx`, `PlatformDelivery.jsx`, `PlatformCardEditor.jsx`: 생성 직후 JPG 확인, 동적인 준비 상태, 오류 표시·수동 재확인, 미리보기 측정 시점 일치.
- `src/lib/cardPreparation.js`(신규), `platformState.js`: 준비·재사용 공통 흐름, 오류 메타데이터를 문안 검수 서명에서 제외.
- `article_editor/dev/tests/card-preparation.test.mjs`, `platform-generator/tests/card-jpg-studio.test.cjs`, `card-preparation-layout.test.cjs`(신규): 준비 상태·실제 컴포넌트·실제 JPG 회귀 시험.
- `package.json`: 신규 준비 상태 시험을 기본 `npm test`에 포함. 프론트 빌드 산출물 재생성.

기존 미커밋 변경은 유지했다. Core 코드·계약, Instagram/Threads 생성 규칙, 표지·마지막 카드 작성 규칙은 이번 수정에서 변경하지 않았다. 커밋·push·PR은 실행하지 않았다.

## 자동 검증 및 한계

- 준비 함수: 생성 후 완료, 수정 카드만 재렌더, 실패 후 정상 보관, 부분 첨부 금지, 다른 고정본 거부, 검수 재호출 없음, 횟수·시간 기록.
- 실제 편집실 컴포넌트의 격리 브라우저 시험: Instagram+카드 생성, JPG 자동 확인, 3번 실패 표시, 편집 후 재확인, 정상 자산 재사용, SNS 준비에 전체 장수·순서·같은 기사/고정본 전달. 생성·Core 응답은 모의이며 유료 AI·외부 SNS 호출은 없다.
- 실제 Chromium 렌더: 실제 3번 문안의 수정 전후, 미리보기/JPG 측정 일치, 사진 유무, 실제 넘침·겹침 거부 유지.
- `npm test`: 54개 통과(API 경계 검사 포함). 별도 격리 편집실 브라우저 시험 1개, 실제 Chromium 레이아웃/JPG 시험 1개, 기존 편집실 SSR 시험 1개 통과. 최초 테스트 하네스의 모듈 로딩 오류는 수정했으며 최종 제품 경로 시험은 통과했다.
- `npm run build` 통과. 기존 editorial.js 정적/동적 import 혼용 경고는 남아 있다.

이번 수정은 새로 생성된 실제 AI 문안 품질을 평가한 것이 아니다. 심한 넘침·사용자 위치 겹침은 자동 삭제·축소·분할로 감추지 않고 준비 실패를 표시한다. 외부 Instagram 로그인·화면 변화·전송 제한은 별도의 실패 원인이 될 수 있다.
