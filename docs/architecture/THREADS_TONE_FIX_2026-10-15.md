# Threads 기본 반말 적용 및 검증 — 2026-10-15

현재 작업 브랜치: `feature/platform-generator`. 기존 미커밋 변경을 보존했다. 커밋·push·PR·게시는 실행하지 않았다.

## 적용 내용

- `platform-generator/lib/threads-tone.js`: 생성·검수·편집 화면에서 기본 반말과 다른 명백한 기사체·존댓말 종결을 함께 확인한다. 직접 인용과 사용자가 명시한 다른 문체는 예외로 둔다. 이 검사는 한국어 형태소 분석이나 의미 검수를 대체하지 않는다.
- `platform-generator/text-generator.js`: 정상 결과에는 추가 호출을 하지 않는다. 문제 문단만 한 번 교정하고 제목·정상 문단·태그·근거 배열은 그대로 둔다. 교정에도 문제가 남으면 성공으로 처리하지 않는다.
- 교정 요청에서 전체 작성 규칙을 다시 적용하던 부분을 제거했다. 새 내용 요약·재구성 대신 종결 말투만 바꾸도록 지시하고 숫자·단위·직접 인용 표기를 보존한다. 0부터 시작하는 입력 문단 번호를 스키마의 허용값으로 제한했다.
- 교정 응답 순서는 문단의 정체성이 아니다. 반환 순서가 달라도 유효하고 중복 없는 문단 번호로 연결한다. 누락·중복·잘못된 번호는 계속 차단한다.
- 실패 원인은 `REPAIR_COUNT`, `REPAIR_INDEX`, `REPAIR_EMPTY`, `NUMBER_CHANGED`, `QUOTE_CHANGED`, `TONE_REMAINS`로 구분한다. 사용자에게 문단 번호와 이유를 알리며 원문·AI 전체 응답·비밀값을 오류 메시지에 넣지 않는다.
- `platform-generator/draft-validator.js`: 기존 저장 원고도 기본 반말 위반을 지적한다. 사실·원문 근거·의미 검사는 유지한다.
- `src/components/ThreadsEditor.jsx`: 기존 저장 원고는 자동 변경하지 않고 편집·재생성을 안내한다. 공용 말투 모듈을 개발 서버와 프로덕션 빌드 양쪽에서 불러올 수 있도록 연결했다.

## 검증

- 최신 코드 기준 `threads-tone.test.cjs`, `threads-tone-ui.test.cjs`, `generation-recovery.test.cjs`, `writing-rules.test.cjs`: 36개 통과.
- `platform.test.cjs`: 12개 통과. 합계 48개이며 서로 다른 테스트 파일 집합이다.
- 화면 테스트는 합성 데이터로 개발 서버와 프로덕션 빌드를 각각 열어 경고 표시, 직접 편집 후 경고 해제, 근거 보존, 지정 문체 예외와 렌더 예외 없음을 확인했다. 이전 테스트 하네스의 인라인 JSX 파싱 오류도 외부 `.jsx` 엔트리로 고쳤다.
- 정상 결과의 AI 요청 1회, 말투 보완 시 2회, 이모지 보완까지 함께 필요하면 최대 3회임을 모의 응답으로 확인했다. 반복 재시도는 없다.
- `npm run build` 통과. 기존 `editorial.js`의 정적·동적 import 병용 경고는 남아 있다. 빌드 산출물만 재생성했으며 Core 구현은 변경하지 않았다.
- `git diff --check` 통과. 기존 CRLF 변환 안내 외 공백 오류 없음.
- 실제 앱에서 현재 저장 기사 적용 및 Threads 편집 화면·재생성 버튼 표시를 확인했다. 기사 원문·계정 정보는 이 기록에 포함하지 않는다.

## 실제 AI 검증과 남은 한계

실제 Threads 재생성 클릭은 자동 승인 검토가 차단했다. 기사 원문을 설정된 외부 AI(Gemini 어댑터)에 전송하고 비용이 발생할 수 있으므로 해당 전송의 명시적 승인이 필요하다는 이유였다. 우회 호출하지 않았으며 이번 검증에서 실제 AI 호출은 실행되지 않았다. 실제 AI의 새 결과·교정 횟수·완료 시간·사용 요금은 미확인이다.

사용자 첨부 화면의 이전 실패 메시지는 여러 실패 원인을 같은 문구로 처리한 결과이므로 그 실행의 정확한 실패 필드를 소급 특정할 수 없다. 확인된 코드 문제를 수정했으나 해당 실제 실패가 해결됐다는 주장은 하지 않는다. 새 실패가 발생하면 문단 번호와 실패 코드로 구분할 수 있다.

수치·인용 문자열 보존은 의미 보존의 충분조건이 아니다. 새 초안의 사실·조건·불확실성·의미 검수 및 사람의 최종 확인은 계속 필요하다. 기존 저장 초안은 규칙 변경으로 자동 교체하지 않는다.
