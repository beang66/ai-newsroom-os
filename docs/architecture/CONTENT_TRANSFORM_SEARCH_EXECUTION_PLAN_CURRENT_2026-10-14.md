# 콘텐츠 변환 검색 비교: 현재 코드 기준 실행 계획

기준일: 2026-10-14 (Asia/Seoul)  
기준: 작업 브랜치 `work/content-transform-main-sync-20261014`의 `b5c1442`, 확인한 `origin/main` `253da6a`  
상태: **계획 개정만 완료. B1 검색·색인·계측 미구현, 실제 AI 호출·품질 실험 미실행.**

실행 조건 보완: B1의 **모의 검색은 연결 시험**이다. 준비한 후보를 올바른 고정본·초안에 전달하고 검색 실패 시 B0로 돌아오는지 확인할 수 있으나, 실제 근거 회수율·오류 감소·속도는 판단할 수 없다. Core 입력 형태는 이 모의 실행과 **병행하여 조기에 확인**한다. 실제 AI 파일럿 전에는 카드뉴스 실제 생성 경로의 실패 여부를 별도 통과 조건으로 확인한다. 현재 카드뉴스 생성·검수 관련 모의 회귀 22개는 통과했지만, 이것만으로 실제 AI 제공자 경로의 오류가 없다고 단정하지 않는다.

원래의 [오류 분류·플랫폼별 정답 기준·지표 정의](CONTENT_TRANSFORM_SEARCH_EXPERIMENT_2026-10-14.md)와 [Core 연결 계약 초안](CONTENT_TRANSFORM_SEARCH_CONTRACT_PROPOSAL_2026-10-14.md)을 이 문서의 상세 근거로 사용한다. 두 문서의 작성 당시 상태·호출 수 설명과 현행 코드가 다른 부분은 아래 기준이 우선한다. 이 계획은 팀 Core나 제품 기능을 변경한 기록이 아니다.

## 1. 현재 구현과 비교의 출발점

| 영역 | 현재 확인한 상태 | 실험에 미치는 영향 |
| --- | --- | --- |
| 고정본 | Core의 `article_snapshots`와 `PlatformManager._from_snapshot`이 제목·`body_text`를 생성/검수에 전달 | 동일한 고정본 ID·내용을 세 군에 사용 가능 |
| 구절 검사 | 원문에 있는 `source_evidence`와 구조를 검사 | 세 군 모두 유지. 인용 일치는 의미·시점의 정답 판정이 아님 |
| B0 위치 문맥 | `quote-context.js`가 본문 일치 위치와 인접 문단을 계산하며, `draft-validator.js`가 두 검수 요청에 `evidence_context`를 보냄 | B0는 제품 코드에 이미 적용됨. 별도 임베딩 호출 없음 |
| 생성 중 B0 | 카드뉴스 생성 과정도 `validateDraft`를 호출 | B0가 최종 검수뿐 아니라 생성·교정에 영향을 줄 수 있음 |
| 검수 재사용 | 카드뉴스의 검수 결과 결합 및 화면의 동일 입력 검수 재사용/다시검수 구현 | 카드뉴스는 새 생성 결과가 결합되면 명시적 검수 API 2회를 생략할 수 있음 |
| B1 의미 검색 | Core 검색 점수 함수는 있으나 저장 색인은 Source 전용; 고정본 검색 API·청크 위치 매핑·수명 계약 없음 | 제품의 스위치를 켜서 B1을 실행할 수 없음 |
| 사용량 계측 | 최종 플랫폼 결과에 원본 AI 응답 `usage`가 없음 | UI 결과에서 토큰을 역산하지 않고 실험 호출 경계에서 계측해야 함 |

기존 17파일 SHA-256 기준선은 작성 시점의 변경 여부 증거다. 현재 그중 `card-news-generator.js`, `draft-validator.js`, `PlatformReview.jsx`, `src/api/platform.js` 4개가 달라졌다. 현재 코드/모델/규칙 해시와 커밋을 새 실험 manifest로 기록하며, 과거 기준선 파일은 덮어쓰지 않는다. Core의 외부 팩트체크 상위 근거 3→5개 변경은 기사 전체 팩트체크에 관한 것으로, 콘텐츠 변환의 별도 검수에 B1이 연결됐다는 뜻은 아니다.

## 2. 무엇을 비교할지 먼저 고정

| 군 | 검수 입력 | 생성 단계 | 외부 임베딩 |
| --- | --- | --- | --- |
| A 대조군 | 전체 고정본·전체 플랫폼 규칙·현행 구절 검사. `evidence_context`와 의미 검색 보조는 전달하지 않음 | 카드뉴스 자동 검수에서도 문맥 입력 끔 | 없음 |
| B0 현행 문맥 | A + 실제 `quoteContexts` 결과와 문맥 해석 지침 | 카드뉴스 자동 검수에도 현행 B0 적용 | 없음 |
| B1 검색 보조 | B0 + **같은 고정본에서** 찾은 모호/미연결 주장 후보와 반대·예외 문맥 | 생성 단계는 B0와 동일. 첫 시험에서는 최종 명시적 검수에만 B1 후보 추가 | 문서·질의 캐시 미스 때만 |

세 군 모두 생성 입력의 전체 기사, 해당 플랫폼 전체 규칙, 두 최종 검수의 사실→편집/요구사항 순서, 출력 스키마, 카드 배분표·교정 규칙을 유지한다. 검색 후보는 참고 위치이며 `source_evidence`를 자동 교체하거나 통과 판정으로 사용하지 않는다. B1 미준비·실패·시간 초과 시 **B0** 입력으로 검수하고 `fallback_reason`을 기록한다. B0 자체 문맥 추출이 실패하면 전체 원문 검수를 유지한 A 형태로 진행하고 별도 실패로 기록한다.

비교용 문맥 선택은 운영 화면에 노출하지 않는 **격리 실험 어댑터**에서만 수행한다. A를 만들기 위해 팀 Core/공통 화면이나 현재 제품의 B0 동작을 되돌리지 않는다. 실험의 `arm`, `context_version`, `trigger_policy_version`, 규칙/모델/스키마 해시를 매 실행에 고정한다. 입력 메시지에서 `evidence_context`를 없애는 것뿐 아니라 A에 남는 B0 전용 지침도 없애야 한다. 이 어댑터의 결과 결합·검수 캐시가 다른 군으로 흘러가지 않도록 실험 군·입력 해시를 분리한다. B1 모의 후보는 연결을 검증하기 위한 fixture이며 실제 검색기가 찾아낸 후보로 평가표에 넣지 않는다.

## 3. 두 실험과 실제 사용 시간

### 실험 I: 고정된 초안의 검수 누락 비교

1. A 설정에서 플랫폼별 자연 초안을 한 번 생성해 고정한다. 오류 주입 복사본과 정상 대조본을 만들고 사람 두 명이 원문 위치·심각도·플랫폼별 필수 정보 단위를 독립 표기한 뒤 합의한다. 카드 배분표도 초안과 함께 고정한다.
2. 같은 초안·고정본·키워드·요구사항을 A/B0/B1에 복제한다. 생성 중 검수의 차이는 이 실험에 들어가지 않는다. 각 군에서 사실과 편집/요구사항 **두 검수 요청을 반드시 새로 실행**한다. `generation_review_binding` 또는 `reusableReview`를 통한 생략은 측정 대상에서 제외한다.
3. 군 순서를 교차하고 모델/규칙/프롬프트/출력 스키마를 기록한다. 원본 AI 입력 캐시가 실제로 적용되면 사용량에 별도 표기한다. B1 트리거는 정답 라벨이나 앞 군의 AI 판정 없이 초안 필드에서만 결정한다.
4. 오류 미탐·핵심 누락 미탐·과잉 지적·호출·토큰·검수 시간을 플랫폼별로 비교한다. 같은 초안이므로 **실제 초안의 핵심 누락 수는 모든 군에서 동일**하다.

### 실험 II: 기사 선택부터 최종 검수 완료까지

1. 동일한 익명화 기사·키워드·요구사항·플랫폼을 군별 격리 복사본에서 독립 실행한다. 기사 선택→불러오기→적용/저장/고정→생성→기존 교정→**명시적 최종 검수 1회**→화면 상태 적용까지 단조 시계로 잰다. 동일한 고정본 내용·해시·모델·규칙을 사용한다.
2. A의 카드뉴스 자동 검수에는 위치 문맥을 넣지 않는다. B0/B1은 현재 코드처럼 위치 문맥을 넣고, B1의 검색은 최종 검수에만 추가한다. 생성 결과의 확률적 차이와 교정 횟수를 별도 기록한다. 결과 품질 차이는 검색 효과만으로 귀속하지 않는다.
3. 세 군에서 최종 검수를 강제로 한 번 실행해 검수 효과와 전체 시간을 같은 경계에서 비교한다. 카드뉴스 생성 중 검수 결과가 화면에 재사용 가능한 상태여도 이 **주 비교에서는 재사용하지 않는다**. 생성 중 실제 검수·교정 요청은 모두 총 호출/시간에 포함한다.
4. **실제 사용 보조 측정**에서는 현행 B0 화면의 재사용 정책을 그대로 두고 ‘기사 선택→검수 완료’ 시간과 추가 검수 호출 수를 별도로 측정한다. 카드뉴스가 재사용되어 최종 검수 호출이 없으면 B1 검색도 호출되지 않는 경로다. 이를 B1의 품질 개선 사례에 섞지 않는다. B1의 운영 적용을 검토할 때는 재사용 결과에 검색이 왜 필요한지 별도로 정한다.

정상 기본 요청 수는 강제 최종 검수 기준 Instagram 3회, Threads 3회, 카드뉴스 6회(배분표 1 + 초안 1 + 생성 중 검수 2 + 최종 검수 2)다. 카드뉴스 검수 재사용이 유효한 실제 사용 경로의 기본값은 4회다. 교정·재시도·실패·임베딩은 추가로 기록한다. “완료”는 통과 판정이 아니라 결과/오류 상태가 UI에 적용된 시각이다.

## 4. B1을 위해 추가할 경계와 검증

0. **모의 연결 구현과 병행해** 팀 Core 담당자에게 [고정본 연결 계약](CONTENT_TRANSFORM_SEARCH_CONTRACT_PROPOSAL_2026-10-14.md)의 최소 입력·출력 형태를 확인한다. 적어도 `snapshot_id`, `article_id`, 요청자가 기대하는 고정본 해시, Core가 인증 상태에서 판정하는 계정/워크스페이스 소유 범위, `source_field`, 원문 `start`/`end`와 좌표 단위·정규화 버전, 오류 상태를 합의해야 한다. 클라이언트가 임의로 주장한 사용자 ID만으로 소유권을 인정하지 않는다. 확정 전 fixture는 교체 가능한 어댑터 경계 뒤에 두고 모의 JSON을 최종 Core API라고 부르지 않는다.
1. 확인한 계약을 바탕으로 격리 실험용 어댑터가 `snapshot_id`/`article_id`/소유 범위/고정본 해시를 확인하고 `body_text`에서 본문 순서·중복 발생을 보존한 청크와 원문 span을 만든다. Source ID 또는 Source 저장 색인을 고정본 ID로 가장하지 않는다.
2. 현재 B0의 위치 단위는 **UTF-16**이다. Core의 원문 span 단위/정규화 버전과 문서의 제안 좌표를 하나로 합의하고, 경계에서 명시 변환한다. 이모지·CRLF·중복 구절·제목에만 있는 구절을 왕복 검사한다. 후보가 원문 본문 span으로 복원되지 않으면 직접 인용 근거로 제공하지 않는다.
3. 별도 폐기 가능 실험 저장소에 색인을 둔다. 최초 청크·문서 임베딩, 신규 질의 임베딩, 캐시 적중과 네트워크 배치를 구분한다. 임베딩 공간 ID/역할/정확한 텍스트/청킹 버전이 일치할 때만 벡터 재사용을 검토한다. 운영 vault·사용자 DB를 실험 캐시로 쓰지 않는다.
4. DenseFly×2·BM25/RRF는 후보 순위용으로만 사용한다. 개발용 기사에서 대상 최대 4개·상위 후보 5개·앞뒤 이웃·보조 입력 상한 2,000토큰을 시험한 뒤 정책 버전을 고정한다. 누락/모호 인용과 수치·시점·조건·직접 인용만 사전 정의한 트리거로 조회한다. 후보가 없거나 실패해도 전체 원문과 기존 검수는 유지한다.
5. 검색 후보와 B0 문맥이 서로 다른 고정본·버전·계정에서 섞이지 않는지, 동시 요청·취소·색인 실패·문서/질의 캐시 오염·HTTP/IPC 동작을 격리 fixture로 확인한다. 검색 추가로 Core의 기존 기사 팩트체크/공통 화면 동작을 바꿔야 한다면 별도 영향 검토를 먼저 한다.

## 5. 계측, 비용 단계, 채택 기준

필수 결과는 플랫폼별 **오류 미탐률, 실제 핵심 정보 누락률과 그 검수 미탐률, AI 요청 수, 공급자 사용량 토큰, 기사 선택→검수 완료 시간**이다. 과잉 지적, 근거 후보 회수율, 실패/재시도/fallback, 최초 색인 시간, 캐시별 시간을 함께 기록한다. 사실/편집 검수, 생성/교정, 문서/질의 임베딩을 따로 센다. 실패한 B1도 분모에서 빼지 않는다. 중앙값·p95는 표본 수와 함께 제시하며 작은 파일럿의 p95를 일반 성능으로 말하지 않는다.

Node→Core의 AI 호출 경계에서 원본 응답 `usage`, 실제 요청 모델, 요청 수/재시도, 단조 시각을 수집하고 임베딩 경계도 별도 계측한다. 공급자가 반환하지 않는 토큰은 `null`로 둔다. 원문 전체·API 키·JWT는 로그에 넣지 않고 해시/fixture ID로 연결한다. 요청 본문 길이나 화면 결과로 토큰을 추정한 값은 공급자 사용량과 구분한다.

| 순서 | 산출물과 통과 조건 | 외부 AI 호출 |
| --- | --- | --- |
| 0. 현재 기준 고정 | 커밋/17파일+신규 파일 해시, 규칙·모델·프롬프트, 격리 자료, 라벨 기준/호출 상한 기록 | 없음 |
| 1. 모의 응답 + Core 계약 확인 | A/B0/B1 선택, 같은 초안/고정본, 강제 검수, 모의 후보 전달·오류·B0 fallback·계측을 결정적으로 검사. 동시에 Core 담당자와 ID/소유권/span/좌표 형태를 검토하고 fixture를 갱신 | 없음. 모의 B1의 검색 품질·속도 주장은 금지 |

실제 파일럿의 첫 상한은 1건의 익명화 기사 × 3플랫폼 × 고정 초안 1개 × 3군인 실험 I(정상 18회 검수 LLM 요청)과, 1기사 × 3플랫폼 × 3군의 한 캐시 조건인 실험 II(정상 36회 생성·검수 LLM 요청)로 제안한다. 이는 **효과 판정용 표본이 아니라** 측정·연결 확인용이다. 재시도/교정은 이 숫자에 포함되지 않는다. 실제 비용과 요청 상한은 모의 계측이 정상인지 확인하고 실계정 실행 전에 정한다. 유료 호출을 이 문서 작성 단계에서 실행하지 않는다.

B1이 B0보다 중대한 오류를 새로 놓치거나 핵심 누락/과잉 지적을 늘리면 자동 연결을 보류한다. 품질 이익이 확인되지 않거나 토큰·전체 시간이 불리하면 B0를 유지한다. B1이 문맥형 오류 미탐을 줄인 경우에도 검색 발동률·실제 사용 경로의 검수 재사용률을 고려해 선택적 적용 범위를 정한다. 정확도·품질·실행시간을 모두 실측 전에는 개선이라고 표시하지 않는다.
