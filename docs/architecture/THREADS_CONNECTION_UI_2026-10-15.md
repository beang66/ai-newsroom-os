# Threads 연결 UI 간소화

작업 브랜치: `feature/platform-generator`. 기존 미커밋 작업을 보존했으며 커밋·push·PR·게시·AI 호출은 실행하지 않았다.

## 판단 및 반영

버튼만 합치면 기존 connect의 홈 재이동, 준비 중/완료 후 재연결 거부, 페이지 닫힘 후 pending 잔존 때문에 작성 내용 보호가 불충분했다. 해당 서비스 처리와 함께 반영했다.

- `PlatformDelivery.jsx`: Instagram 상태 조회 훅을 두 플랫폼에 공용으로 적용했다. Threads는 `Threads 로그인 연결`, `Threads 작성창 채우기`로 표시하며 별도 수동 확인·닫기 버튼은 제거했다.
- Threads의 기존 브라우저 선택과 자동 대체 순서는 유지한다. Instagram Chrome 고정 및 숨김 JPG 렌더러는 그대로다.
- 기존 status를 2초 간격으로 직렬 조회한다. 화면 이탈·준비 작업 시 예약을 정리하고 늦은 응답을 무시한다. busy/pending은 대기로 처리한다. 이미 연결된 창·준비된 작성창에는 connect를 다시 호출하지 않는다.
- Threads의 기존 account 함수는 프로필 이름으로 로그인 계정을 확인한다. `profile_not_identified`를 로그아웃으로 단정하지 않고 계정 이름/로그인 여부 확인이 필요하다고 안내한다. 새 쿠키 기반 로그인 판정이나 Core 반환 필드를 추가하지 않았다.
- Threads의 카드 없는 원고 준비를 유지한다. 카드가 있으면 기존 전체 JPG 준비·보관·최신성 경로를 사용한다. prepare의 success/status/id/image_count를 확인하고 게시하지 않았음을 표시한다.
- `threads-local-service.js`: 새 빈 페이지만 공식 URL로 이동하고 기존 페이지·작성창은 보존한다. 페이지와 창 닫힘 시 pending을 정리하고, 준비 중 닫힘을 명확히 안내한다. 닫힌 컨텍스트의 잠금 해제를 기다리며 내부 close와 종료 정리는 유지한다.

## 검증

- 서비스/기존 플랫폼/브라우저 테스트 17개 통과: 기존 16개 및 새 Threads 합성 DOM 테스트 1개.
- 새 Threads 합성 DOM에서는 선택 브라우저 인자 유지, 계정 확인, 카드 없는/있는 준비, 줄바꿈, 준비 후 재연결 시 내용·pending 보존, 페이지/창 닫힘, 입력 도중 닫힘, 종료 직후 재연결, 게시 버튼 미실행을 확인했다.
- Instagram·Threads 실제 React 컴포넌트 테스트 1개 통과: 두 버튼, 자동 로그인 확인, 중복 클릭, 조회 최대 동시 수 1, busy/pending, 생성 중 정리, 늦은 응답 무시, 기존 연결에 connect 재호출 없음, 계정 미확인 안내, Edge 선택 전달 및 실제 연결 브라우저 표시, Threads 카드 없는 준비, 닫힘 후 준비 안내 제거를 확인했다.
- `npm run build`, API 경계 검사 통과. 기존 editorial.js 동적/정적 import 중복 경고는 유지된다.
- 실제 앱 `http://127.0.0.1:5173/#convert`의 Threads 편집 화면에서 두 버튼과 브라우저 선택 UI를 확인했다.

## 한계

실제 Threads 로그인·카드 업로드·원고 입력까지는 검증하지 않았다. 합성 DOM의 테스트 통과를 실제 사이트 완료로 해석하지 않는다. 실행 중인 SNS 서비스에 새 서버 모듈을 적용하려면 로컬 앱/Core 재시작이 필요하다. 열린 창과 작업 보호를 위해 강제 종료하지 않았다.

원고 생성 규칙, Core 계약, 이미지 보관·전체 첨부 정책은 이번 작업에서 변경하지 않았다.
