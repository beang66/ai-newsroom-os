# 보안 모델 — 데스크톱 앱 (자산 · 경로 · 규칙 · 백로그)

- 상태: **문서 확정(2026-10-02)** · 구현은 **백로그(P1~P4)** 로 순차 진행
- 범위: 로컬 우선 데스크톱 앱(웹뷰 + App Core)과 우리 백엔드/Supabase 연결
- 관련: `../ARCHITECTURE.md`(키·접근 경계), `IPC_MIGRATION.md`(전송), `../../APP_CORE_ARCHITECTURE.md`(Core 구조)

## 1. 전제

> **앱(코어 포함)은 신뢰 경계가 아니다.**
> 운영키·비밀키는 앱에 넣지 않는다. 앱에는 "백엔드 주소 + 사용자 토큰"만 둔다.

이 문서의 목적은 "로컬에 있으니 안전하다"는 가정을 걷어내고, **어디서 무엇이 나갈 수 있는지**를
명시한 뒤 우선순위를 정하는 것이다.

## 2. 자산 (무엇을 지키는가)

| 자산 | 어디에 있나 | 노출 시 피해 |
|---|---|---|
| **원고·취재자료** | 로컬(JSON·IndexedDB) + AI 호출 시 전송 | 기사 내용 자체, **기자·취재원 위험** |
| 사진·이미지 | 로컬(원본·축소본) + 캡션 생성 시 전송 | 인물·장소 특정, 촬영정보 |
| 사용자 JWT | 코어 메모리(+재발급용 refresh) | 그 사용자 권한(짧음, 서버 폐기 가능) |
| 운영키(OpenAI, `service_role`) | **백엔드에만** | 전체 데이터·과금 |
| 앱 무결성 | exe·업데이트 | 개조본 유포, 자격 탈취 |
| 로컬 저장소 전체 | `.article-workspace/` | 위 자산의 평문 사본 |

## 3. 신뢰 경계

```
[웹뷰]  ← 가장 노출. XSS·서드파티 스크립트·확장·원격 콘텐츠. 토큰은 모른다.
   │ 계약(api.*)만
[App Core] ← 같은 프로세스. UI보다 신뢰하지만 **기기 소유자에게는 비신뢰**(개조·덤프 가능)
   │ HTTPS
[백엔드 / Supabase(RLS)] ← 최종 판정자. 권한·과금·한도를 여기서 결정
```

## 4. 위협 모델

| 공격자 | 무엇을 얻나 | 현재 완화 | 남은 위험 |
|---|---|---|---|
| 클라우드 침해 | 저장된 것 | 원고 **평문은 클라우드에 저장하지 않음**(Control Plane + 공유 계층만) | 공유 기능 도입 시 암호화·키 관리 |
| 웹 콘텐츠 취약점(XSS·확장·원격 스크립트) | 페이지가 볼 수 있는 모든 것 = **원고 포함** (JWT는 코어 보관으로 차단) | 계약 경계, 브리지 최소 노출(예정) | CSP·원격 콘텐츠 금지 미적용 |
| 기기 소유자·개조 | JWT, 로컬 평문, 백엔드 주소 조작 | 운영키는 앱에 없음 → 얻을 게 제한적 | 토큰 수명·폐기 정책은 백엔드 구현 과제 |
| 악성코드·원격 접속(RDP/TeamViewer)·사내 DLP | 실행 중 메모리, 파일 | 없음(로컬 암호화로도 실행 중엔 무효) | 앱 잠금·세션 타임아웃이 보조 |
| 네트워크 도청·중간자 | 전송 중 원고·토큰 | HTTPS | 인증서 고정(pinning) 미적용 |
| 백업·동기화·수리·중고 | 로컬 폴더 사본 | 없음 | **동기화 폴더 감지 경고**(P1) |

## 5. "기기 탈취 없이" 나가는 경로 (오해 정리)

"원고는 로컬이니 기기를 뺏기지 않는 한 안전하다"는 **성립하지 않는다**. 실제 경로:

| # | 경로 | 지금 상태 |
|---|---|---|
| 1 | **AI 호출 자체가 원고 전송** (저장 ≠ 전송) | `store:False`(`app/core/ai/client.py:21`, `router.py:72`), `시작하기.md` 고지, 백엔드 프록시는 무저장 정책 |
| 2 | **웹뷰는 원고를 반드시 안다** (화면에 그려야 함) | JWT는 감췄지만 원고는 브리지로 반환됨 → CSP·원격 콘텐츠 금지가 곧 원고 보호 |
| 3 | **동기화 폴더·백업** (OS/서드파티가 업로드) | 없음 → **P1 경고 기능** |
| 4 | **폴더 복사·수리·중고** (평문 저장) | 없음 → **P1 로컬 암호화** |
| 5 | **실행 중 메모리·원격 접속·DLP** | 없음(범위 밖 명시 필요) |
| 6 | **공유 기능** (예정) | 규칙만 존재(평문 업로드 금지, 암호화본만) |

## 6. 현재 저장 실태 (사실 · 근거)

| 저장물 | 위치 | 상태 |
|---|---|---|
| 원고 | `.article-workspace/articles/<id>.json` | **평문 JSON**(`app/core/storage.py:20` `json.dumps`, 사람이 그대로 읽음) |
| 자동 임시저장 | `.article-workspace/webview/EBWebView/Default/IndexedDB/` | **평문 LevelDB**(Chromium 미암호화) |
| 로그 | `.article-workspace/logs/app.log` | 원고·키 미기록(원칙, `app/core/api.py:15` "Do not log manuscript content or API credentials") |
| 프로필 캐시 | 같은 `webview/` | 앱 JS·히스토리 잔존 → 폴더 전체를 민감정보로 취급 |

검증 예시(실제 저장 파일):

```json
{ "title": "계약 검증",
  "bodyHtml": "<p>문장입니다. 문장입니다. …</p>",   ← 본문이 평문
  "articleId": "a569b0e1…" }
```

→ 폴더가 복사·동기화·백업되면 원고가 그대로 나간다. **암호화 전까지는 평문으로 취급**한다.

## 7. 구현 규칙 (지금부터 코드 리뷰 체크리스트)

1. **운영키·secret을 앱(코어 포함)에 넣지 않는다.** 앱이 아는 것은 백엔드 주소 + 사용자 JWT뿐이다.
   (`ARCHITECTURE.md` 하드 규칙. `AI_BACKEND=local`은 개발 전용이며 배포본에 사용 금지)
2. **브리지(`js_api`)에 토큰을 반환하는 메서드를 만들지 않는다.** `getToken()`·`session().token` 금지.
   노출은 "작업(operation)"만. (웹뷰가 탈취되면 페이지는 토큰 없이도 사용자 행세를 할 수 있으므로,
   토큰 자체를 넘기지 않는 것이 최소 요건)
3. **웹뷰에 원격 콘텐츠·외부 스크립트를 로드하지 않는다.** CSP 유지, 원격 페이지 임베드 금지.
4. **원고·사진·토큰을 로그·크래시 리포트·에러 메시지에 남기지 않는다.** (기존 `log_message` 원칙 유지)
5. **클라이언트 주장을 신뢰하지 않는다.** 권한·과금·한도는 서버(RLS·constraint·쿼터)가 최종 판정.
6. **전송은 최소 정보만.** AI 호출 시 필요한 문맥만 보내고, 저장은 `store:False`/무저장 정책을 따른다.
7. **로컬에 남기는 것은 평문이다**고 표시한다(문서·UI 안내). 암호화를 붙이는 시점에 이 문서를 갱신한다.
8. **실패 시 안전(fail closed).** 자격·암호화·검증 실패는 통과시키지 않는다.

## 8. 보안 백로그 (앱 구현 후 하나씩)

| 순위 | 항목 | 목적 | 트리거(언제) | 난이도 | 검증 방법 |
|---|---|---|---|---|---|
| **P1** | **동기화 폴더 감지 경고** | 경로 3(동기화/백업) 차단 | 지금 바로 가능 | 낮음 | `APP_ROOT`가 OneDrive/Dropbox/Google Drive/iCloud 하위일 때 `--check`·로그·창 배너에 경고 |
| **P1** | **앱 잠금 + 세션 타임아웃** | 자리 비움·원격 접속 | 다음 UI 작업과 함께 | 중간 | 유휴 N분 후 잠금, 재인증(로컬 PIN/OS 자격) |
| **P1** | **로컬 저장 암호화**(Encryption Manager) | 경로 4(복사·수리·중고) | 저장소 이전 시점 | 높음 | `articles/*.json`·IndexedDB 대체 저장소 암호화, 키는 사용자/프로젝트(`ARCHITECTURE.md:74`) |
| **P2** | **웹뷰 경화**(CSP·원격 금지·브리지 최소화) | 경로 2(XSS) | IPC 전환과 함께 | 중간 | `--check`에 CSP 확인, 브리지 메서드 목록 점검(토큰 반환 없음) |
| **P2** | **토큰 수명·회전·폐기**(refresh, `devices`) | 기기 소유자·도난 | 백엔드 구현 시 | 중간 | 401→refresh→실패 시 로그인 화면, 기기별 폐기 |
| **P3** | **앱 서명 + 서명된 업데이트** | 경로(개조본 유포) | 배포 채널 확정 시 | 중간 | exe 서명, 업데이트 서명 검증(현재는 unsigned → SmartScreen 경고) |
| **P3** | **HTTPS 인증서 고정(pinning)** | 경로(중간자) | 백엔드 도메인 확정 시 | 중간 | 잘못된 인증서로 접속 실패 확인 |
| **P4** | **공유 기능 보안 설계** | 경로 6 | 공유 기능 착수 시 | 높음 | 평문 업로드 금지, 키 관리·RLS 검증 |
| **P4** | **취재원 보호 수준 점검** | 메타데이터 최소화 | 요구가 생길 때 | 높음 | 사진 EXIF·위치정보 제거, 클립보드/스크린샷/인쇄 정책 |

핵심 원칙: **P1은 "로컬에 있어도 나가는 경로"를 막는 것**이고, P2 이상은 기능(백엔드·공유)이 붙을 때 함께 처리한다.

## 9. 지금 상태에서 이미 되어 있는 것

- 운영키가 앱에 없음(코어는 `.env` 또는 백엔드 프록시, 배포 기본은 `AI_BACKEND=remote`)
- AI 요청에 `store:False`(외부 모델 측 저장 거부)
- 원고·키를 로그에 남기지 않음(`log_message` 비활성)
- 프론트는 토큰·백엔드 주소를 모름(계약만 호출) → XSS가 토큰을 직접 읽지 못함
- **로그인 토큰은 코어가 보관**(`app/core/auth.py`)하고, `GET /api/session` 은 토큰 없이 상태만 준다
- Supabase는 **anon 키만** 사용(service_role은 백엔드 전용), 백엔드 호출은 로그인 JWT를 우선 사용
- 로컬 모델은 **SHA-256 검증 후에만** 사용(불일치 시 파일 삭제) — `app/core/managers/model_manager.py`
- 로컬 전용 바인딩(127.0.0.1)·배타 바인딩(포트 탈취 방지)·Origin 검사

## 10. 나중에 이 문서를 갱신할 시점

- P1(동기화 경고·앱 잠금), P1(로컬 암호화)를 구현할 때 → §6 표와 §8 표를 실제 상태로 바꾼다
- 백엔드/JWT가 붙을 때 → §4의 "남은 위험"을 갱신하고 토큰 보관·회전 정책을 확정한다
- 공유 기능 착수 시 → §5의 6번을 별도 문서로 분리한다
