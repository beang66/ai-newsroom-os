# 팀 저장소 인계 메모 — Critique / 자료 정리·Explore

## 지금 올릴 단위

이 폴더 전체를 팀 저장소의 독립 경로(예: `prototypes/critique-organizer/`)에 **코드 파일 그대로** 올립니다. 기존 팀 서버나 UI의 같은 이름 파일을 덮어쓰거나 기본 브랜치에 곧바로 합치지 않습니다. 기능 브랜치에서 Draft PR을 열고, 담당 범위와 미완료 사항을 리뷰어에게 공유합니다. ZIP은 전달용이며 Git에는 압축파일 대신 소스·테스트·문서를 추적합니다.

## 경계와 연결 지점

| 부분 | 현재 위치 | 팀 통합 시 필요한 연결 |
|---|---|---|
| 기사 검토 규칙 | `app/critique.py`, `app/review.py` | 팀 기사 초안 모델과 Finding 계약 연결 |
| OpenAI | `app/openai_adapter.py`, `app/model_proofread.py` | 팀 서버의 비밀 환경 변수 `OPENAI_API_KEY`, 요청 권한·사용량 정책 |
| 자료 정리·탐색 | `app/knowledge.py`, `app/organization.py` | 팀 자료/취재 건 ID와 접근 권한, 삭제 정책 |
| 로컬 검색·저장 | `app/retrieval.py`, `app/store.py` | 담당자의 RAG 및 공통 DB와 어댑터로 교체 |
| 미리보기 서버·UI | `app/server.py`, `web/`, `run.py` | 로컬 데모 전용. 팀 서버·화면을 덮어쓰지 않고 `docs/contracts.d.ts`의 계약을 사용 |

현재 SQLite와 바닐라 JS UI는 단일 사용자 로컬 미리보기입니다. 팀 운영 서비스의 인증, 사용자별 권한, 큐, 다중 사용자 저장소가 구현됐다는 뜻이 아닙니다. `docs/INTEGRATION.md`에 요청/응답 및 출처 위치 검증 계약이 있습니다.

## 이미 확인된 문제

- 맞춤법: 로컬 자동 검사는 8개 규칙뿐입니다. OpenAI 검사도 후보 최대 30건이며 맥락에 따라 실제 오류를 누락하거나, 원문 위치가 안 맞아 제안을 제외할 수 있습니다. 예: `알음알음`을 `아름아름`으로 바꾼 문장은 *문맥에 따라* 오류이므로 전체 문장과 기대 교정을 함께 기록해야 합니다. `아름아름` 자체를 항상 오류로 판정하면 정상 용례를 해칩니다.
- 외부 OpenAI 계정의 실호출과 실제 브라우저 렌더링은 이 개발 환경에서 확인하지 못했습니다. 테스트 모의 응답과 HTTP/상태 검사만 통과했습니다.
- 사실 검증은 외부 자료 검색이 아니며, 선택 자료의 후보 발췌와의 제한된 비교입니다. 법적 판정도 제공하지 않습니다.

## 리뷰 전에 확인할 항목

1. `python -m pip install -r requirements.txt` 후 `python -m unittest discover -s tests -q`, `node --test tests/*.test.cjs`.
2. 로컬 `.env`는 Git에 올리지 않습니다. `.env.example`만 추적합니다. 키가 Git 기록에 들어갔다면 삭제 커밋만으로 해결되지 않으므로 키를 폐기하고 새로 발급해야 합니다.
3. OpenAI 키를 설정한 개발자가 **API 연결 확인**을 눌러 상태를 확인하고, `OpenAI 사용`을 체크한 뒤 송고 전 점검합니다. 테스트 실패 문구와 재현 원고를 이슈에 남기되 키·비공개 취재자료는 남기지 않습니다.
4. 팀의 RAG, STT, 편집기, 미리보기 및 형식 변환 담당자와 API 필드/자료 ID/소유 저장소를 확정하기 전에는 통합 완료로 표시하지 않습니다.
