# 팀 테스트 안내 (실행 · 데이터 · 문제 보고)

## 1. 실행
- ZIP을 풀고 `AINewsroom.exe`를 실행합니다. 설치는 필요 없습니다.
- 처음에 Windows가 "PC를 보호했습니다"(SmartScreen)를 띄우면 **추가 정보 → 실행**을 누릅니다(서명 없는 앱이라 나오는 경고입니다).
- 로그인해야 기사와 자료를 볼 수 있습니다. 로그인 창의 "회원가입"으로 각자 계정을 만들 수 있고, 기사·자료는 계정마다 따로 보관됩니다. 계정 도입 전에 쓰던 자료는 **처음 로그인한 계정**이 이어받습니다(이전 전에 `vault.pre-accounts.db`로 복사본을 남깁니다).
- 로그인할 때 "이 PC에서 로그인 유지"를 켜면 다음에 앱을 열 때 바로 로그인됩니다(환경 설정에서 끌 수 있고, 로그아웃하면 꺼집니다). 비밀번호는 저장하지 않고 로그인 유지용 토큰만 Windows 자격 증명 관리자에 보관하므로 공용 PC에서는 켜지 마세요.
- 팩트체크 모델은 앱 안의 설정(모델 설치)에서 받습니다. 처음 한 번만 받습니다.
- 카드뉴스 이미지를 만들려면 Edge나 Chrome이 있어야 합니다(Windows에 기본으로 있습니다).

## 2. 내 데이터는 어디에 있나
| 데이터 | 저장 위치 | 밖으로 나가는 경우 |
|---|---|---|
| 기사, 취재자료, 사진, 녹취 | 내 PC의 암호화 저장소 `%LOCALAPPDATA%\AI Newsroom\vault-<계정 id>.db` (계정마다 파일이 따로) (열쇠는 Windows 자격 증명 관리자) | 아래 표 참고. 팀 서버에는 저장되지 않습니다. |
| 로그인 계정 정보 | 팀 계정 서버(Supabase) | 계정(이메일)만 저장됩니다. 기사·자료는 올라가지 않습니다. |

**기능을 쓸 때 서버로 나가는 내용** (서버는 처리만 하고 저장하지 않습니다)
- 팩트체크: 자료 조각과 검증할 문장이 임베딩 서비스(Cloudflare)로 전송됩니다. 상위모델 재검토를 누르면 해당 문장과 근거 조각 최대 3개가 OpenAI로 전송됩니다.
- 제목·부제 추천, 사진 키워드, 흐름 요약: 본문이 AI 서비스로 전송됩니다.
- 사진 검색: 검색어가 Unsplash로 전송됩니다.

**주의**
- 시험에는 공개돼도 되는 기사·자료를 쓰거나, 비공개 자료라면 위 전송 내용을 알고 쓰세요.
- 계정 분리는 앱 안에서 다른 계정의 자료가 보이지 않게 하는 것이며, 같은 PC의 같은 Windows 사용자는 같은 열쇠를 쓰므로 PC 자체를 보호하는 수단은 아닙니다.
- `vault-*.db`를 지우거나 옮기면 작성한 글이 사라집니다. 지우려면 사이드바 설정(모델 설치 창)의 백업 내보내기로 먼저 저장하세요.
- 시험이 끝나면 `%LOCALAPPDATA%\AI Newsroom` 폴더를 지워 데이터를 없앨 수 있습니다.
- 팀에 파일을 보낼 때 `vault*.db`, `.env`, 원고, 자료는 넣지 마세요.

> 예정(아직 없음): 기사 자동 서버 공유, 자료 공유 요청.

## 3. PC를 바꿀 때 (자료 이전)
환경 설정 → "다른 PC로 이전" → "이전 마법사 열기".
1. **옛 PC:** "서버로 보내기"를 누르면 현재 계정의 자료가 **일회용 코드로 암호화**되어 서버로 올라가고, 코드(예: `ABCDE-FGHJK-LMNPQ-RSTUV`)가 나타납니다. 서버에는 암호문만 있고 코드는 가지 않습니다. 코드는 이 창에서만 보이니 적어 두세요. 계정마다 서버에는 한 칸만 있고, 다시 보내면 덮어씁니다("서버에서 지우기"로 취소할 수 있음).
2. **새 PC:** 옛 PC와 같은 계정으로 로그인한 뒤 마법사의 "새 PC에서 가져오기"에서 서버 상태를 확인하고 코드를 입력하면, 이 PC의 현재 계정 자료가 이전 자료로 바뀝니다(바꾸기 전 자료는 안전 복사본으로 남음). 가져오면 서버 파일은 자동으로 지워집니다.
3. 자료가 서버 한도(50MB)를 넘으면 안내가 나옵니다. 그때는 "파일로 만들기"로 파일을 만들어 메신저·클라우드·USB로 옮기고, 새 PC에서 "이전 파일로 가져오기"를 쓰세요(파일은 코드가 없으면 열 수 없지만, 코드는 파일과 다른 방법으로 전달하세요).

> 관리자(백엔드 담당) 준비: 서버 경유 이전을 쓰려면 Supabase 에 `article_editor/integration/supabase_transfer_bucket.sql` 을 한 번 실행해 비공개 저장 공간(`transfers`)과 접근 규칙을 만들어야 합니다.

## 4. 작성 중 기사 클라우드 백업
환경 설정의 "작성 중인 기사를 클라우드에 백업"(기본 켜짐)은 **기사 본문과 저장 이력만** 암호화해서 서버에 올립니다. 사진·취재자료·녹취는 올리지 않고 이 PC에만 있습니다.
- **언제 올라가나:** 저장 버튼(Ctrl+S)은 바로, 자동 임시 저장은 마지막 변경 후 30초쯤 조용하면 올라갑니다(계속 쓰는 중에도 5분마다 한 번). 앱을 닫을 때 한 번 더 올립니다. 서버에는 기사마다 최신 작업본과 마지막 수동 저장본 한 칸만 둡니다.
- **열쇠:** 우리 서버가 관리해서 사용자가 따로 보관할 것이 없습니다. 새 PC에서는 같은 계정으로 로그인한 뒤 환경 설정의 "서버 백업에서 복구"에서 기사를 골라 복구합니다(이 PC의 기존 저장 이력은 지우지 않고 새 저장본으로 추가됩니다).
- **알아 둘 점:** 기사는 발행용이라 보안 민감도가 낮다는 판단으로, 서버 관리자도 이론상 기사를 풀 수 있게 설계했습니다(저장소(Supabase)만 침해되면 암호문만 보입니다). 민감한 내용은 취재자료에 두세요(로컬 전용).
- **끌 때:** 확인 창에서 "서버에 있는 내 백업도 삭제할지" 고를 수 있습니다.
- 인터넷이 없거나 서버에 문제가 있으면 설정 창에 "백업이 지연되고 있어요"가 나오고 자동으로 다시 시도합니다(저장 자체에는 영향이 없습니다).

> 관리자(백엔드 담당) 준비: Render 에 환경변수 `BACKUP_MASTER_KEY`(32자 이상 무작위, 바꾸거나 잃어버리면 기존 백업을 풀 수 없음)를 넣고, Supabase 에 `article_editor/integration/supabase_transfer_bucket.sql` 이 실행되어 있어야 합니다(이전 마법사와 같은 버킷).

## 5. 문제가 생기면
아래를 복사해 단체방에 보내 주세요. **기사 내용은 보내지 않아도 됩니다.**
```
[문제 보고]
무엇을 하다가: (예: 팩트체크 전체 다시 검증을 누름)
어떻게 됐나: (화면 문구 그대로 / 캡처)
기대한 것:
다시 해도 생기나: 예 / 아니오
```
- 저장 실패는 `%LOCALAPPDATA%\AI Newsroom\logs\storage-errors.jsonl`(시각·종류만 있고 내용은 없음)을 함께 보내 주세요.
- 앱 버전과 모델 설치 상태를 한 번에 복사하는 기능은 아직 없습니다. 필요하면 앱 주소 끝에 `/api/status`를 붙여 열어 나오는 글을 복사해 주세요.
