# 취재자료 자동 정리·3D Explore v0.4

이 문서는 v0.4 범위 기록입니다. v0.5의 명시적 OpenAI 제안과 적용 흐름은 [README.md](../README.md) 및 [INTEGRATION.md](INTEGRATION.md)를 참조하세요.

## 실제 제공 범위

원본 보존형 가상 분류, 취재 건 연결, 공통 목록/그래프 필터, 연결 근거에서 원문으로 이동하는 흐름을 구현했다. 기존 Critique는 유지하며 비교 자료 선택을 공유한다. 로컬 단일 사용자용이며 인증·클라우드 동기화·운영 배포를 포함하지 않는다.

| 단계 | 동작 | 명시적 제한 |
|---|---|---|
| 가져오기 | 파일·폴더, 중복 내용 감지, 현재 선택한 취재 건 연결 | PC 원본 이동/삭제/이름 변경 없음. 동일 바이트는 최초 파일명·경로로 보관하며 추가 이름 이력은 저장하지 않음 |
| 자동 정리 | 유형 5종+미분류, 주제 9종의 규칙 제안, 이름+직책 인명/기관명 후보 | 생성형 AI 분류가 아닌 사전 정의 규칙. 복수 유형은 미분류. 전체 기관·인물 인식 불가 |
| 요약 | 앞의 두 텍스트 블록에서 각 최대 180자 원문 발췌와 위치 | 핵심 의미를 생성·요약하지 않음. 발췌 미리보기라고 표시 |
| 수정 | 유형·태그·자료 날짜·복수 취재 건 편집, 마지막 변경 되돌리기 | revision 충돌 시 저장 거부. 되돌리기는 1단계이며 새 revision 발행 |
| 실패 처리 | 한도 내 실패 파일의 원본·이유 보관, 재시도·다운로드·명시적 영구 삭제 | 10MB 초과/위험한 경로는 보관하지 않음. 실패 파일에는 파일명 검색만 적용 |
| 검색 | 파일명·상대 경로·태그·본문의 부분문자열, 유형·취재 건·기간·처리 상태 필터 | 의미 검색은 팀 RAG 연결 영역. 등록일은 UTC, 자료 날짜는 사용자가 확인해 입력 |
| STT 연결 | JSON으로 제공된 발언·초 단위 시간 구간 등록, 원본 JSON 다운로드 | 음성 인식/화자 식별은 수행하지 않음. 오디오 원본은 번들에서 보관·재생하지 않음 |
| 3D | ID 기반 고정 구면 좌표의 3차원 투영, 회전·확대·선택 중심 이동·연결 확장 | Canvas 2D에 3D 좌표를 투영. WebGL 엔진은 아님. 공간 거리·크기는 의미/중요도/신뢰도가 아님 |

## 코드 책임

- `app/organization.py`: 분류·태그·발췌·이름 출현 위치 생성. 저장·외부 모델 호출 없음.
- `app/knowledge.py`: 메타데이터, 취재 건, 이력, 필터, 그래프, 실패 원본 및 STT 입출력 서비스. SQLite 연결만 `store`에서 재사용.
- `app/server.py`: 로컬 HTTP 라우팅과 입력 전달.
- `web/knowledge.js`: 자료 관리 전용 컨트롤러. 기존 `app.js`의 기사 버전·원문 보기와 작은 연결 지점만 공유.
- `docs/contracts.d.ts`: 팀 UI에서 재사용할 API 계약. 데모 DOM/CSS를 React에 그대로 합치는 방식은 권장하지 않음.

기존 스키마 2와 원본 테이블을 유지하고 organization/projects/organization_history/intake_failures 네 테이블을 추가한다. 원본 데이터 재작성은 없다. 이전 자료는 처음 조회할 때 분류를 생성하며 이미 저장된 사용자 변경은 재업로드해도 유지한다. 분류 엔진을 교체하려면 `organization.describe(title, blocks)`의 반환 계약과 정확한 원문 범위를 유지해야 한다. 외부 모델 연결 시 전송 동의, 구조 검증, 근거 위치 검증을 별도로 구현해야 한다.

## API 2.2

| 메서드·경로 | 입력 | 응답/책임 |
|---|---|---|
| POST `/api/intake` | name, path?, base64 data, project_id? | ready/duplicate/failed 상태. 실패도 정상 JSON 응답에 명시 |
| GET `/api/catalog` | q, type, project, status, date_field, from, to | 자료 목록·분류·프로젝트·실패 목록·전체/검색 건수 |
| GET `/api/organized/:id` | 문서 ID | 원문 블록·분류·취재 건 연결 제안 |
| POST `/api/projects` | title | 새 취재 건. 같은 제목도 서로 다른 ID |
| GET `/api/projects` | 없음 | 취재 건 목록 |
| POST `/api/organization` | document_id, revision, changes | 수정된 분류. changes 허용 필드만 처리 |
| POST `/api/organization/undo` | document_id, revision | 마지막 분류 변경 복원 |
| GET `/api/explore` | catalog 필터 + focus, depth(1~3), limit(1~150), node_kind | 제한된 노드·연결·표시/숨김 건수 |
| POST `/api/transcripts` | title, segments[{start,end,text}] | STT 문서 ID·중복 여부·시간 위치. 시간은 초 |
| GET `/api/failed-original/:id` | 실패 ID | 원본 다운로드. 실행 가능한 파일도 attachment로만 제공 |
| POST `/api/intake/retry` | failure_id | 저장 원본으로 재처리 |
| POST `/api/intake/remove` | failure_id | 실패 보관 원본 영구 삭제 |

기존 `/api/documents`, `/api/search`, `/api/reviews`는 유지한다. `/api/graph`는 기존 이름 후보 API이며 새 화면은 `/api/explore`를 사용한다. 같은 이름으로 병합하지 않는 정책은 새 Explore에 적용된다. 취재 건 연결은 JSON 메타데이터의 여러 project_ids로 저장되며 프로젝트 영구 삭제 API는 제공하지 않는다.

## 관계의 의미

- `filed_in`: 사용자가 지정한 취재 건 연결. 사실 주장이나 출처 검증 상태가 아니다.
- `tagged`: 규칙 제안 또는 사용자 태그. 규칙 제안에는 근거 구간을 포함한다.
- `mentions`: 해당 문서의 해당 위치에서 이름 형태가 등장한다. 노드 ID는 문서·블록·출현 위치에 종속되어 동명이인을 병합하지 않는다.
- 사람↔사람, 소유·공모·인과관계 추론은 없다. 비슷한 이름의 통합도 없다.

UI에서 사용자 연결은 실선, 규칙 제안은 점선이다. 노드 또는 선을 선택하면 이유와 원문 이동을 제공한다. 키보드 사용자는 아래 노드 목록에서 같은 상세 패널을 열 수 있다. 전체 필터 결과 중 기본 60개, 최대 150개를 표시한다. 선택한 취재 건은 기본 1단계 주변만 보여주고 ‘연결 더 보기’로 최대 3단계 확장한다. ID 기반 좌표를 유지하므로 클릭만으로 좌표를 다시 무작위 배치하지 않는다. 필터 변경은 동일하게 목록/그래프에 적용된다.

## 검증·운영 한계

Python 70개, JavaScript 10개 자동 테스트. 자료 등록→분류 수정→그래프→원본 다운로드 HTTP 흐름, 중복 원본, 수정 충돌, 되돌리기, 필터, 삭제 연쇄, 실패 원본, 동명이인 분리, 원문 오프셋, STT 유효성·시간 위치, 늦은 상세 응답 차단을 포함한다.

JS 테스트는 최소 DOM 모형이다. 브라우저 실행 도구와 Chromium이 없는 환경이므로 실제 데스크톱·모바일 렌더링 및 클릭 검증은 미완료다. Jev 실호출 역시 미검증이다. 로컬 소규모 데이터용 전체 스캔이므로 대규모 자료에서 성능 SLA를 보장하지 않는다. 파일 업로드는 동기 처리하며 작업 큐·자동 재시도·다중 사용자 권한은 후속 범위다. 원본은 SQLite에 평문 보관한다.

자동 분류/연결의 정확도는 이 테스트 개수로 입증되지 않는다. 실제 기자 자료 평가 후 규칙 또는 모델 어댑터를 확장해야 한다.

## 실행 확인 순서

1. `python -m pip install -r requirements.txt` 후 `python run.py` 실행.
2. 취재자료 화면에서 ‘교통 취재’를 만들고 선택한 뒤 `examples/source.txt` 업로드.
3. 목록에서 자료를 선택하여 발췌·분류 단서·원문 위치 확인.
4. 태그 수정→저장→되돌리기. 다시 같은 파일을 올려 중복 안내 확인.
5. 3D Explore→취재 건/자료 선택→연결 더 보기→주제·인명 후보나 연결선 선택→원문 위치로 이동.
6. ‘현재 기사 자료로 연결’ 후 기사 검토 화면에서 기존 Critique 실행.
7. STT 입력에 `examples/transcript.json` 내용을 붙여 넣고 등록. 원문 시간 위치 확인.
