> **2026-10-18 갱신(이후 진행분):** 회원가입·작성 중 기사 서버 백업·이전 마법사·IPC 전환·스냅샷 연결·렌더 결과 MediaAsset 등록·Data Map 읽기 모델·자료 목록/삭제 호출은 구현됐다. 남은 것: 앱 잠금, 자료·팀 공유(S1), 계약 v1.0 확정, ProcessingJob 의 AI 기능 전체 연결. 현재 상태는 `docs/architecture/CURRENT_IMPLEMENTATION_MATRIX_v0.8.md` 의 "구현 현황"과 `docs/team/TEAM_TEST_GUIDE.md` 를 본다.

사용자 결정: 남은 작업은 꼭 필요한 것만 먼저 하고 나머지는 후순위로 미룬다.
추가 테스트는 현재 진행하지 않는다. 구현을 마친 뒤 전달 직전에 기본 흐름을 한 번 점검한다.
기존에 구현한 기능은 유지하며, 아래 기준으로 신규 개발의 우선순위만 줄인다.

## 이번 완료 기준

HTTP 방식 Windows EXE에서 팀 계정으로 로그인하고, 기사 한 건을 작성·저장하고,
취재자료를 올려 로컬 팩트체크를 실행하고, 플랫폼 원고를 생성한 뒤,
앱을 다시 열었을 때 기사·자료·생성 결과를 이어서 사용할 수 있어야 한다.
팀원 PC에는 Python/Node 개발 환경이 있다고 가정하지 않는다.

## 먼저 해야 할 일

| 항목 | 최소 작업 | 이유 |

자료 업로드 서버 테스트에서 database is locked와 임시 DB 정리 WinError 32가 관찰됐다.
백그라운드 색인 작업을 기다리지 않는 시험 정리의 영향일 수 있으므로,
이를 실사용 데이터 손실로 단정하거나 전체 저장소 구조를 바꾸지 않는다.
실제 기본 흐름을 막는 원인과 해당 시험의 작업 종료/정리 처리만 좁게 해결한다.

## 첫 팀 테스트 이후로 미룬 일

- `GET /api/articles/<id>` 및 기사 경로 하이픈 UUID 지원: 현재 화면의 필수 소비 경로는 latest/save이다.
  새 계약 어댑터나 기사 선택 화면이 실제로 사용하기 시작할 때 작은 호환 패치를 적용한다.
- Data Map 전체 기사·자료·스냅샷 읽기 모델 연결, 검색/목록 개선.
- 자료 전역 목록·삭제/강제 삭제 화면. 기존 업로드·자료 참조 기능은 유지한다.
- 스냅샷 생성 시점 결정과 화면의 snapshotId 연결, 렌더 결과 MediaAsset 등록.
- 모든 AI 기능의 공통 ProcessingJob 연결 및 통합 진행률/취소 화면.
  기존 모델 설치 진행/취소와 source_ingest 작업은 유지한다.
- UI의 expectedRevisionNo/409 충돌 처리: 다중 창/동시 편집 지원 단계에서 연결.
- IPC 전환, 계약 v1.0 확정, 전체 문서 재작성.
- ONNX int8/fp16 경량화, 긴 문맥 한계/속도/RAM 비교, 대규모 색인 성능 실험.
  대표 문장·질의·검색 순위의 기본 정확도 확인은 전달 직전 점검에 남긴다.
- 자료 유사도 군집, 회원가입, 이전 마법사, 서버 백업, 앱 잠금, AI 수정안.
- 임시 폴더/원격 브랜치 정리, 일반 디자인 개선.

## 작업 순서

1. 발견한 저장·업로드 오류는 위 TODO 부채로 기록하고 수정 유예(사용자 최신 요청). 실사용 장애가 확인되면 해당 항목만 다시 우선 처리.
2. generator/Node 준비 완료. 이미 연결된 Hugging Face 매니페스트와 준비된 packaging/vendor를 포함해 최신 EXE 빌드.
3. 미커밋 작업·짧은 안내서 정리.
4. 구현이 모이면 기본 흐름을 한 번 점검한 뒤 팀 테스트에 전달.

정리 항목은 기능 완료 표시가 아니다. 푸시는 기존 규칙대로 사용자가 요청할 때만 한다.
