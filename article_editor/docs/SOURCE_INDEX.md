# 취재자료 청크 색인

자료 원본, 추출 본문, 청크, 임베딩은 모두 로컬 SQLCipher 저장소에 둡니다.
평문 청크 파일이나 별도 벡터 DB를 만들지 않으며 네트워크를 사용하지 않습니다.

## 저장 테이블

- `sources`: 자료 ID, 원본 파일, 추출 본문, 이름과 워크스페이스.
- `source_chunks`: 자료 ID와 순번을 복합 기본키로 사용합니다.
  본문은 `text`, 종류·필드·자료 메타데이터는 `meta_json`에 보관합니다.
  `vector_key`는 해당 청크의 문서 임베딩 키입니다.
- `source_index`: 자료별 상태, 본문 SHA-256, 청커 버전,
  청크 수, 짧은 오류 코드와 갱신 시각을 기록합니다.
- 두 색인 테이블 모두 `workspace_id`를 보관합니다.
- `embedding_vectors`: 기존 모델·역할·텍스트 기반 벡터 캐시입니다.
  동일 텍스트의 문서 벡터는 여러 자료에서 공유합니다.

## 상태와 실행 시점

- `pending`: 모델 또는 런타임이 없거나 본문이 변경되어 재색인이 필요합니다.
- `ready`: 해당 본문과 청커 버전의 청크·문서 벡터 저장을 마쳤습니다.
- `failed`: 청커 또는 인코더에서 오류가 발생했습니다.
  `CHUNKER_ERROR` / `ENCODER_ERROR`만 기록하며 원문은 오류에 넣지 않습니다.
- 업로드 추출 직후 `source_ingest` 작업을 백그라운드에서 시작합니다.
  응답에는 `indexJobId`, `indexState`가 추가되며 임베딩 완료를 기다리지 않습니다.
  `indexing`은 응답에서만 사용하는 작업 진행 표시입니다.
- UUID가 없는 옛 16자리 자료 ID는 업로드 작업을 만들지 않습니다.
- 모델이 없으면 업로드는 성공하고 색인은 `pending`으로 남습니다.
  이 경우 작업 자체는 정상 종료하며 모델을 자동 다운로드하지 않습니다.

## 팩트체크 재사용과 갱신

`ready`이고 본문 해시와 청커 버전이 같으면 저장된 본문 청크를 읽습니다.
현재 요청의 제목·날짜·화자로 검색용 메타데이터를 구성하므로 기존 결과와 같습니다.
조건이 맞지 않으면 기존과 같은 공통 청커로 계산합니다.
저장된 자료 본문과 요청 본문이 같으면 계산한 청크와 벡터를 지연 저장합니다.
따라서 모델 설치 후 첫 팩트체크도 대기 중 자료를 색인할 수 있습니다.
경계 모델은 선택 사항이며 설치 유무가 바뀌면 청커 버전도 달라집니다.
같은 파일과 본문을 다시 올리면 기존 색인을 유지합니다.
본문 변경은 대기 상태로 돌리고, 자료 삭제는 청크와 색인만 함께 지웁니다.
공유 벡터는 삭제하지 않습니다. 최종 저장 시 삭제·본문 변경 여부를 다시 확인합니다.
1024차원 float32 벡터는 청크당 약 4 KB이며 본문·메타데이터·DB 공간은 별도입니다.
