# 기사 작성 워크스페이스 v14

## 실행

1. 압축을 새 폴더에 모두 풉니다.
2. 기존 `.env`를 이 폴더에 복사하거나 `.env.example`을 복사해 `.env`로 이름을 바꿉니다.
3. `.env.example`의 설명대로 키를 입력합니다. Application ID와 Secret Key는 현재 기능에 사용되지 않아 비워도 됩니다. 기존 OpenAI 키를 유지하고 `UNSPLASH_ACCESS_KEY=발급받은 Access Key`를 추가합니다. **Unsplash Secret Key는 필요하지 않습니다.** 키를 HTML이나 GitHub에 넣지 마세요.
4. Windows: `start_windows.bat` 더블클릭. Mac/Linux: `python launcher.py`.

Python 3.10 이상이 필요합니다. 실행 창을 열어 둔 채 사용하세요. 이전 앱과 겹치지 않도록 8877~8899 중 빈 포트를 선택합니다. `index.html`을 더블클릭하거나 `screenshots` 폴더의 PNG를 여는 것은 앱 실행이 아닙니다.

## 제목·부제

- 본문을 작성한 뒤 입력칸을 클릭하면 아래에 추천을 표시합니다. 입력 중에는 최초 추천만 준비하고, 추천이 생긴 뒤 계속 자동 생성하지 않습니다.
- 잠금 아이콘: 확정/확정 해제. 확정한 제목·부제는 본문을 수정하거나 새로고침해도 자동으로 다시 생성하지 않습니다. 입력칸은 옅은 회색이 되고 AI 추천도 잠깁니다. 잠금 아이콘을 다시 눌러 확정을 해제해야 수정할 수 있습니다.
- 로봇 + AI 아이콘: 추천을 다시 생성합니다. 확정 중에는 비활성화됩니다. 기존 작성 문구는 추천을 직접 선택하기 전까지 유지합니다.
- 본문 안내: “기사 본문을 작성하면 기사 제목을 추천해드립니다.” / “기사 본문을 작성하면 부제목을 추천해드립니다.”
- 추천창은 입력칸 아래 공간을 펼쳐 다음 칸이나 사진 버튼을 덮지 않습니다. 다른 곳을 클릭하면 닫힙니다.

## 저장하기와 DB

‘저장하기’는 Python 백엔드에 현재 원고를 전달하여 **실행 폴더 안 `.article-workspace/articles/<기사ID>.json`**에 저장합니다. 동일 원고를 다시 저장하면 같은 파일을 갱신합니다. 제목·부제·서식·본문·사진 원본/편집본·출처·확정 상태를 포함한 JSON입니다. 파일마다 임시 파일에 쓴 뒤 교체하며 기사ID는 경로에 사용할 수 없는 값을 거부합니다.

입력을 잠시 멈추면 0.6초 후 브라우저에 임시 저장하고, 1.5초 후 하드디스크 원고 파일도 자동 저장합니다. ‘저장하기’는 즉시 저장할 때 사용할 수 있습니다. 화면 하단 저장 상태와 본문 글자 수는 스크롤·미리보기 전환 후에도 고정 표시됩니다. 여러 원고를 다룰 때 `draft-key`(React: `draftKey`)에 기사별 고유 값을 전달하세요. 이전 브라우저 임시 원고도 이어서 읽습니다.

**현재 로컬 저장에는 서버 DB가 필수가 아닙니다.** 과거 기사 목록 화면은 별도 구현 대상입니다. 로컬 JSON을 읽거나 로컬 SQLite를 사용할 수 있습니다. 팀 공용 기사 보관소, 회원정보, 로그인 승인, 인스타그램 계정 연동은 인증과 권한·토큰 관리를 담당하는 팀 백엔드/DB에 연결해야 합니다. 이 작업에서 로그인·인스타그램 연동 기능을 새로 구현하지 않았습니다.

## 사진 넣기

‘사진 넣기’ 메뉴에는 두 가지 선택지만 있습니다.

- **사진 검색하기**: 중앙 팝업에서 본문 기반 검색어 3개 추천 → 검색어 클릭 → Unsplash 사진 3장 → ‘편집해서 넣기’ 또는 ‘다운로드’.
- **사진 첨부하기**: 내 파일 선택 → 사진 편집 화면 → 본문에 넣기.

사진 자체를 클릭해도 편집 화면으로 이동합니다. 검색 결과에는 API가 반환한 이미지 URL과 사진가/Unsplash 출처를 표시합니다. 사진 선택·다운로드 시 `download_location` 추적 요청을 보내며 Access Key는 Python 서버에서만 사용합니다. 사진 편집용 원본도 API 이미지 URL로 읽고 선택한 원본 파일은 별도로 보관합니다. 사용자가 선택·편집한 파일은 원고에 포함됩니다.

사진 설명 추천은 제거했습니다. 사진 설명·출처는 직접 입력합니다. 다운로드한 자료사진이 실제 기사 사건의 현장 사진이라는 뜻은 아닙니다.

### 사진 편집

- 원본/16:9/4:3/1:1/3:2 표시 비율 선택.
- 확대 슬라이더 없이 **표시 범위의 네 모서리를 드래그해 크기 조절**. 선택한 비율은 유지됩니다. 범위 안쪽을 드래그해 위치를 옮깁니다.
- ‘모자이크’를 켜고 가릴 부분을 칠합니다. 브러시 크기로 칠하는 범위를 조절합니다.
- ‘되돌리기’로 마지막 칠하기·지우기·이동 작업을 취소합니다. 캔버스에서 Delete 키도 지원합니다.
- 원본/편집본 각각 다운로드할 수 있습니다. 편집본은 최대 가로 1600px이며 원본보다 확대하지 않습니다. 기사에는 비율을 유지해 맞춥니다.
- 본문 사진 박스를 드래그해 위치를 바꾸거나 ‘사진 편집’으로 다시 편집합니다.

원고 작성·첨부 사진 편집·로컬 저장은 인터넷이 없어도 사용할 수 있습니다. Unsplash 검색과 OpenAI 추천·요약에는 인터넷 연결과 해당 키가 필요합니다.

## 요약 보기

첨부 화면을 기준으로 중앙에 1,040×394px 팝업을 띄웁니다. 작은 화면에서는 화면 크기에 맞춥니다. 배경은 검은색 반투명으로 표시하고, 팝업 밖 클릭·닫기·Esc로 닫습니다. 새로고침 버튼으로 요약을 갱신합니다. 주요 문단/소제목의 핵심을 전개 순서에 맞춰 **3~5개의 짧은 문장**으로 보여주며 ‘문제 제기·배경·역할’ 라벨과 긴 조언은 제거했습니다. 번호는 화면에서만 작게 표시합니다.

기본 `FLOW_SUMMARY_PROVIDER=openai`는 OpenAI 모델로 원고 전체를 요약합니다. `FLOW_SUMMARY_PROVIDER=kobart`로 설정하면 기존 KoBART 모델이 문단 묶음을 요약하고 OpenAI가 3~5개 핵심 문장으로 정리합니다. KoBART는 `requirements-headline.txt` 설치 및 모델 캐시가 필요합니다. 설치되지 않은 모델을 사용했다고 표시하지 않습니다. 제목·부제의 기존 KeT5/KoBART 파이프라인도 `USE_LOCAL_MODELS=true`로 선택할 수 있습니다.

## 팀 통합과 CSS

- `assets/article-workspace.js`: 기능 Web Component + Shadow DOM.
- `assets/theme.css`: 편집 화면 스타일. `theme-url`로 다른 테마를 붙일 수 있습니다. 기능은 `data-*` 속성으로 동작합니다.
- `assets/donga-preview.css` / `donga-fonts.css`: 미리보기만 사용하는 독립 스타일/글꼴. 넓은 PC 화면의 본문684px/18px/32.4px, 제목676px/34px/47.6px을 기준으로 화면 폭에 따라 레이아웃을 바꿉니다.
- `react/ArticleWorkspace.tsx`: React 연결 래퍼. 제목·부제·본문 값은 서식을 포함한 HTML입니다.
- `article-change` 이벤트: 원고 내용 변경. `article-saved` 이벤트: 실제 저장 성공.

```html
<script type="module" src="/article/assets/article-workspace.js"></script>
<article-workspace theme-url="/article/assets/theme.css" draft-key="article-001"></article-workspace>
```

React 프로젝트에서는 `ArticleWorkspace`의 `initialValue`, `onChange`, `themeUrl`, `apiBase`, `draftKey`를 사용합니다. 배포 시 assets 파일도 정적 자산으로 함께 제공해야 합니다. `apiBase`만 다른 출처로 바꾸는 방식은 로컬 서버의 Origin 정책 때문에 동작하지 않습니다. 같은 출처 프록시를 쓰거나 아래 API를 팀 백엔드에 옮겨야 합니다.

| API | 역할 |
|---|---|
| `POST /api/articles/save` `{draft}` | 하드디스크 원고 저장 |
| `POST /api/assist` `{kind:'metadata',requested:'headline'/'subheadline',body,current_headline}` | 제목/부제 추천 |
| `POST /api/assist` `{kind:'photo_keywords',body}` | 검색어 3개 추천 |
| `GET /api/unsplash/search?q=...` | 사진 3장 검색 |
| `GET /api/unsplash/photo/{id}` | 선택/다운로드 기록 후 원본 가져오기 |
| `GET /api/unsplash/photo/{id}/track` | 별도 다운로드 기록 |
| `POST /api/assist` `{kind:'flow',body}` | 핵심 문장 3~5개 |

`.article-workspace`, `local_data`와 `.env`는 GitHub에 올리지 않습니다. `integration/`는 과거 Supabase 참고 코드이며 새 원고 저장 API에 연결된 기능이 아닙니다.

## v12 사진 편집 변경
- 모자이크를 켜고 사진 위를 칠하면 해당 영역에 가우시안 흐림이 적용됩니다. 크기 조절과 마지막 획 되돌리기를 지원합니다. 원본은 보존하며 편집본에만 적용됩니다.
- 새 사진은 본문 맨 위에 삽입됩니다. 기존 사진 편집은 원래 위치를 유지합니다. 삽입 후 드래그로 이동할 수 있습니다.
- 본문 사진의 외곽 박스를 제거했습니다. 이미지를 클릭하면 사진 편집·사진 설명·삭제하기 도구가 뜨고 다른 곳을 클릭하면 닫힙니다.

## v12 이동 표시와 흐림
- 사진을 끌 때 문단 사이에 2px 청록색 삽입선이 표시됩니다. 표시선은 본문의 자리를 차지하지 않습니다. 반투명 드래그 표시와 화면 가장자리 자동 스크롤은 유지합니다.
- 모자이크는 블록 픽셀 대신 가우시안 흐림으로 표시하며 편집본에도 동일하게 적용됩니다.
- 투명도 0%는 흐림을 온전히 적용하고, 100%는 원본을 보여줍니다. 투명도는 모든 획에 함께 적용되며 편집 정보로 저장됩니다. 겹친 획에도 한 번만 적용합니다.

## v12 자동 저장·글자 수
- 동일 원고를 자동 저장할 때 기존 기사ID 파일을 갱신합니다. 저장 중 수정된 내용은 이어서 저장하므로 이전 요청이 최신 내용을 덮지 않습니다. 파일 저장 실패 시 하단에 표시하고 5초 후 재시도합니다.
- 본문 글자 수는 바이트가 아닌 Unicode grapheme 단위입니다. `가` 1자, `기사` 2자, 결합형 이모지 `👩‍💻` 1자. 공백 포함, 줄바꿈 제외이며 사진·사진 설명·취소선으로 삭제한 글자는 제외합니다.

## v12 사진 메뉴·검색 탐색
- 사진 도구는 이미지를 클릭하면 나타나며, 도구 밖 배경·사진 설명·작성란 여백을 클릭하거나 Esc를 누르면 닫힙니다. 삭제 버튼은 ‘삭제하기’입니다.
- 사진 넣기 버튼은 메뉴를 열었을 때 활성화 표시가 됩니다. 바깥 클릭·Esc·메뉴 선택 시 닫히며 활성화 표시도 해제됩니다.
- 검색 사진 3장 아래 이전·다음 버튼을 배치했습니다. 같은 검색어로 다음 결과를 가져오고 이전 결과는 캐시에서 복원합니다. 새 검색어는 첫 페이지부터 시작하며 마지막 페이지에서는 다음 버튼이 비활성화됩니다.
- 서버에서 Unsplash page/per_page 요청과 total_pages 응답을 전달합니다. 실제 API 검색 순서에 따라 결과가 나옵니다. API 공식 문서: https://unsplash.com/documentation

## v12 지우개·이동·부드러운 경계
- 지우개: 버튼을 선택한 뒤 사진 위를 브러시로 문질러 흐림을 부분적으로 지웁니다. 브러시 크기를 공유합니다.
- 이동: 칠한 영역 위에서 손 모양 커서가 나타납니다. 브러시로 한 번 칠한 영역을 잡아 끌면 모양과 지워진 자국이 함께 이동합니다. 원래 자리는 원본으로 돌아오며 이동한 위치의 사진에 흐림을 적용합니다.
- 경계 선명도: 기본 20%. 낮추면 모자이크와 지우개 가장자리가 부드럽고, 100%는 또렷합니다. 투명도와 별도로 조절하며 편집본 다운로드·본문 삽입에 동일하게 적용됩니다.
- 되돌리기: 현재 편집 화면에서 마지막 칠하기·지우기·이동을 취소합니다.
- 이전 실행 오류를 수정한 launcher.py/start_windows.bat가 포함되어 있습니다.

## v12 바로 삽입·간결한 편집·본문 복사
- 사진 검색: 본문에 넣기는 편집 화면을 거치지 않고 원본 비율로 바로 삽입합니다. 이후 사진 클릭 → 사진 편집을 사용할 수 있습니다.
- 모자이크/지우개 한 획을 마치면 그리기 모드가 해제됩니다. 완성한 흐림 영역을 바로 잡아 드래그하면 이동합니다. 새 획을 그릴 때 모자이크를 다시 선택합니다.
- 편집 슬라이더 수치는 바 오른쪽에 배치하고 모서리 안내를 제거했습니다. 1280×900 화면에서 사진과 본문에 넣기 버튼을 스크롤 없이 볼 수 있도록 검증했습니다. 작은 화면에서는 필요한 경우 스크롤을 허용합니다.
- 본문 복사: 사진과 편집 도구, 취소선으로 삭제한 텍스트를 제외한 본문 전체를 텍스트로 복사합니다.
- 원고 JSON과 포함된 사진 원본/편집본은 앱 폴더의 `.article-workspace/articles`에 자동 저장합니다. Windows에는 숨김 속성을 적용합니다. 저장 파일은 화면·GitHub·다운로드 ZIP에 포함하지 않습니다.

## v12 사진 교체
사진을 클릭 → 사진 교체하기 → 새 파일 선택 → 편집 → 본문에 넣기. 기존 본문 위치와 사진 설명·출처는 편집 화면에 유지됩니다. 새 사진의 설명·출처를 확인하고 적용할 수 있습니다. 이전 사진의 자르기·모자이크는 새 사진에 복사하지 않습니다. 파일 선택 또는 편집 취소 시 본문 사진은 유지됩니다.

## v12 교체 메뉴·아이콘·인쇄·부드러운 이동
- 본문 사진 → 교체하기 → 사진 검색하기 또는 사진 첨부하기. 검색 사진도 기존 사진 자리에서 교체됩니다.
- 본문 위 사진 넣기·요약 보기·본문 복사·인쇄하기는 아이콘으로 표시하고 마우스 올리기/키보드 포커스 시 이름을 보여줍니다.
- 인쇄하기는 동아일보 미리보기로 전환해 기사 영역만 브라우저 인쇄 대화상자에 전달합니다. 편집 도구는 출력하지 않습니다.
- 1280×768 화면에서 사진 편집의 비율부터 본문에 넣기까지 상태바 위에 모두 표시됨을 검증했습니다. 900px 이상 가로 화면에서는 편집 도구를 압축하고 사진은 화면 높이에 맞게 표시합니다. 더 작은 화면에서는 스크롤이 필요할 수 있습니다.
- 사진 이동은 포인터와 requestAnimationFrame 기반 반투명 미리보기·삽입선·자동 스크롤로 구현했습니다. 끝내면 사진을 한 번만 옮기고 자동 저장합니다.

## v13 사진 도구·줄바꿈 이동
- 사진 클릭 시 편집·교체하기·설명 넣기·삭제하기 아이콘을 표시합니다. 마우스를 올리거나 키보드로 선택하면 기능명이 표시됩니다.
- 교체하기의 사진 검색하기/사진 첨부하기 메뉴는 교체 아이콘 바로 아래에 표시됩니다.
- 완료된 모자이크를 클릭해 선택하고 Backspace 또는 Delete를 누르면 해당 모자이크만 삭제합니다. 되돌리기로 복구할 수 있습니다.
- 본문 Enter 문단과 Shift+Enter 줄바꿈 각각을 사진 삽입 위치로 인식합니다. 붙여넣은 DIV 안의 BR과 중첩 문단에서도 텍스트와 강조 서식을 유지합니다.

## v14 위로 이동·반응형 미리보기
- 글자와 BR만으로 입력된 본문도 사진 이동 위치로 인식합니다. 첫 줄 위로 사진 이동 가능합니다.
- 위/아래 자동 스크롤은 전체 페이지와 독립 스크롤 패널 모두 지원합니다.
- 화면 전체 축소를 제거하고 동아일보 실제 기사 CSS의 1280px/1024px/767px 반응형 규칙을 적용했습니다. 제목/본문은 별도로 너비를 계산하며 좁은 화면에서 제목24px/본문18px로 표시합니다.
- GitHub 업데이트: 이 폴더 안의 파일을 기존 작업 브랜치의 article_editor 안에 반영합니다. 공용 앱의 루트 파일은 덮어쓰지 않습니다. 로컬의 기존 .env와 .article-workspace 원고 폴더는 유지하세요.
